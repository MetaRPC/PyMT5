# MT5Service - Методы позиций и ордеров (API среднего уровня)

## ⚠️ Важно: Прочитайте сначала это

**MT5Service - это архитектурный слой** между высокоуровневым (Sugar) и низкоуровневым (Account) API.

### Понимание 5 методов:

| Метод | Ценность прямого использования | Архитектурная роль |
|--------|------------------|-------------------|
| `get_opened_tickets()` | ✅ **СРЕДНЯЯ** - Преобразует protobuf repeated → списки Python | ✅ Используется Sugar |
| `get_positions_total()` | ⚪ **НИЗКАЯ** - Распаковывает `data.total_positions` из protobuf | ✅ Используется Sugar |
| `get_opened_orders()` | ⚪ **НЕТ** - Просто вызывает `account.opened_orders()` | ✅ Используется Sugar |
| `get_order_history()` | ⚪ **НЕТ** - Просто вызывает `account.order_history()` | ✅ Используется Sugar |
| `get_positions_history()` | ⚪ **НЕТ** - Просто вызывает `account.positions_history()` | ✅ Используется Sugar |

### Что это значит:

**Архитектура (3 слоя):**
```
MT5Sugar (ВЫСОКИЙ)     →  service.get_opened_tickets()   ← Sugar использует методы Service
MT5Service (СРЕДНИЙ)   →  account.opened_orders_tickets() ← Service преобразует в списки Python
MT5Account (НИЗКИЙ)    →  gRPC-вызов → protobuf repeated-поля
```

**Ключевое отличие от методов символов:**

- ✅ **Только 1 метод имеет реальную ценность** - `get_opened_tickets()` преобразует protobuf repeated-поля в списки Python
- ⚪ **4 метода - сквозные** - идентичны прямому вызову MT5Account
- ⚪ **Распаковка protobuf** - только `get_positions_total()` распаковывает одно поле (`data.total_positions`)

**Для прямого использования MT5Service:**

- ✅ **Используйте `get_opened_tickets()`** - преобразует в списки Python (чище, чем protobuf repeated-поля)
- ⚪ **Остальные 4 метода** - нет ценности, просто вызывайте MT5Account напрямую

**Для пользователей MT5Sugar:**

- ✅ Все методы работают безупречно - слой выполняет свою архитектурную задачу

---

**Слой API:** **СРЕДНИЙ УРОВЕНЬ** - обёртки над MT5Account с нативными типами Python

**Реализация:**

Эти методы реализованы в `src/pymt5/mt5_service.py`, который оборачивает низкоуровневый API `package/MetaRpcMT5/helpers/mt5_account.py`.

**Файлы примеров:**

- `examples/2_service/04_service_demo.py` - исчерпывающий демо-пример всех методов MT5Service, включая позиции/ордера

## Зачем эти методы существуют

### Реальная ценность: get_opened_tickets()

**Только `get_opened_tickets()` добавляет реальную ценность**, преобразуя protobuf repeated-поля в списки Python:

**Проблема с MT5Account** (низкий уровень):

```python
# MT5Account возвращает protobuf repeated-поля — нужно ручное преобразование в список
tickets_data = await account.opened_orders_tickets()
position_tickets = list(tickets_data.opened_position_tickets)  # ← Ручное преобразование
order_tickets = list(tickets_data.opened_orders_tickets)       # ← Ручное преобразование
```

**Решение с MT5Service** (средний уровень):

```python
# Service преобразует в списки Python автоматически
position_tickets, order_tickets = await service.get_opened_tickets()
# ← Уже списки, а не protobuf repeated-поля!
```

### Остальные методы: Сквозной слой

`get_opened_orders()`, `get_order_history()`, `get_positions_history()` - это **сквозные обёртки**:

**Реализация:**

```python
# get_opened_orders — прямая передача
async def get_opened_orders(...):
    return await self._account.opened_orders(...)  # ← Без обработки!

# get_order_history — прямая передача
async def get_order_history(...):
    return await self._account.order_history(...)  # ← Без обработки!

# get_positions_history — прямая передача
async def get_positions_history(...):
    return await self._account.positions_history(...)  # ← Без обработки!
```

**Зачем они существуют:**

- ✅ **MT5Sugar (высокий уровень) использует их** - поддерживает слоистую архитектуру (Sugar → Service → Account)
- ✅ **Единый интерфейс** - все методы доступны через один класс
- ✅ **Согласованное именование** - префикс `get_*` для всех методов Service
- ⚪ **Без обработки** - прямая передача в MT5Account

**Для конечных пользователей:** Если вы используете MT5Service напрямую (не Sugar), вызов MT5Account идентичен. Эти обёртки не добавляют ценности.

**Для MT5Sugar:** Они необходимы - Sugar должен работать через Service, а не напрямую с Account (слоистая архитектура).

## Все 5 методов

| Метод | Возвращает | Реализация |
|--------|---------|----------------|
| `get_opened_tickets()` | `Tuple[List[int], List[int]]` | ✅ Преобразует protobuf repeated → `(list(...), list(...))` |
| `get_positions_total()` | `int` | ⚪ Распаковывает `data.total_positions` из protobuf |
| `get_opened_orders()` | `OpenedOrdersData` | ⚪ `return await self._account.opened_orders(...)` |
| `get_order_history()` | `OrdersHistoryData` | ⚪ `return await self._account.order_history(...)` |
| `get_positions_history()` | `PositionsHistoryData` | ⚪ `return await self._account.positions_history(...)` |

## Ключевые концепции

### Позиции vs ордера

- **Позиция**: Открытая рыночная позиция (BUY или SELL), которая в данный момент активна
- **Отложенный ордер**: Лимитный/стоп-ордер, ожидающий исполнения
- **Исторический ордер**: Прошлые ордера (исполненные, отменённые или отклонённые)
- **Закрытая позиция**: Позиция, которая была открыта, а затем закрыта (имеет данные P&L)

### Номера тикетов

- Каждая позиция и ордер имеют уникальный **номер тикета** (int64)
- Номера тикетов используются для идентификации, изменения и закрытия позиций/ордеров
- Используйте `get_opened_tickets()` для быстрой проверки существования (намного быстрее, чем полные данные)

## Сигнатуры методов

### 1) get_positions_total

```python
async def get_positions_total(
    self,
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[Any] = None,
) -> int
```

**Получить общее число открытых позиций.**

**Возвращает:** количество `int` напрямую (без структуры Data)

**Использование:** Быстрая проверка наличия открытых позиций перед закрытием всех.

**Технические детали:** Низкий уровень возвращает protobuf с обёрткой `data.total_positions`. Этот метод автоматически извлекает количество.

---

### 2) get_opened_orders

```python
async def get_opened_orders(
    self,
    sort_mode: account_helper_pb2.BMT5_ENUM_OPENED_ORDER_SORT_TYPE =
        account_helper_pb2.BMT5_OPENED_ORDER_SORT_BY_OPEN_TIME_ASC,
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[Any] = None,
) -> Any  # OpenedOrdersData
```

**Получить все открытые позиции и отложенные ордера с полными деталями.**

**Аргументы:**

- `sort_mode`: Режим сортировки результатов (по умолчанию: по времени открытия по возрастанию)

**Возвращает:** protobuf `OpenedOrdersData` с:

- `position_infos`: Список PositionInfo (ticket, symbol, volume, profit, SL/TP и т. д.)
- `opened_orders`: Список OpenedOrderInfo (ticket, symbol, volume, type, SL/TP и т. д.)

**Доступные режимы сортировки:**

```python
BMT5_OPENED_ORDER_SORT_BY_OPEN_TIME_ASC     # Сначала старые
BMT5_OPENED_ORDER_SORT_BY_OPEN_TIME_DESC    # Сначала новые
BMT5_OPENED_ORDER_SORT_BY_ORDER_TICKET_ID_ASC   # По тикету по возрастанию
BMT5_OPENED_ORDER_SORT_BY_ORDER_TICKET_ID_DESC  # По тикету по убыванию
```

**Технические детали:** Возвращает полные данные protobuf со всеми деталями позиции/ордера. Для получения только тикетов (быстрее) используйте `get_opened_tickets()`.

---

### 3) get_opened_tickets

```python
async def get_opened_tickets(
    self,
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[Any] = None,
) -> Tuple[List[int], List[int]]
```

**Получить только номера тикетов (легковесно и быстро).**

**Возвращает:** `Tuple[position_tickets, order_tickets]`

- `position_tickets`: Список номеров тикетов позиций
- `order_tickets`: Список номеров тикетов отложенных ордеров

**Технические детали:** Низкий уровень возвращает OpenedOrdersTicketsData с двумя repeated-полями int64. Этот метод извлекает оба списка без разбора полных деталей позиции/ордера.

**Преимущество:** В 10-20 раз быстрее, чем `get_opened_orders()`, когда вам нужны только ID тикетов для проверки существования или подсчёта.

**Сценарии использования:**

- Проверить, существует ли конкретный тикет
- Быстро подсчитать позиции/ордера
- Отслеживать новые позиции (сравнивать списки тикетов)
- Валидировать тикет перед изменением

---

### 4) get_order_history

```python
async def get_order_history(
    self,
    from_dt: datetime,
    to_dt: datetime,
    sort_mode: account_helper_pb2.BMT5_ENUM_ORDER_HISTORY_SORT_TYPE =
        account_helper_pb2.BMT5_SORT_BY_CLOSE_TIME_DESC,
    page_number: int = 0,
    items_per_page: int = 50,
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[Any] = None,
) -> Any  # OrdersHistoryData
```

**Получить исторические ордера и сделки за период времени.**

**Аргументы:**

- `from_dt`: Время начала (datetime)
- `to_dt`: Время окончания (datetime)
- `sort_mode`: Режим сортировки (по умолчанию: по времени закрытия по убыванию)
- `page_number`: Номер страницы для пагинации (отсчёт с 0)
- `items_per_page`: Элементов на странице (по умолчанию: 50)

**Возвращает:** protobuf `OrdersHistoryData` с:
- `order_history_infos`: Список OrderHistoryInfo (ордера + связанные сделки)

**Доступные режимы сортировки:**

```python
BMT5_SORT_BY_CLOSE_TIME_DESC    # Сначала самые недавние (по умолчанию)
BMT5_SORT_BY_CLOSE_TIME_ASC     # Сначала старые
BMT5_SORT_BY_TICKET_DESC        # По тикету по убыванию
BMT5_SORT_BY_TICKET_ASC         # По тикету по возрастанию
```

**Технические детали:** Возвращает protobuf OrdersHistoryData с repeated-полем. Поддерживает пагинацию для больших наборов результатов.

**Примечание:** Для закрытых позиций с расчётом P&L используйте вместо этого `get_positions_history()` (более детальное отслеживание прибыли).

---

### 5) get_positions_history

```python
async def get_positions_history(
    self,
    sort_type: account_helper_pb2.AH_ENUM_POSITIONS_HISTORY_SORT_TYPE,
    open_from: Optional[datetime] = None,
    open_to: Optional[datetime] = None,
    page: int = 0,
    size: int = 10,
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[Any] = None,
) -> Any  # PositionsHistoryData
```

**Получить историю закрытых позиций с деталями P&L.**

**Аргументы:**

- `sort_type`: Тип сортировки (обязательно)
- `open_from`: Начало фильтра по времени открытия (необязательно)
- `open_to`: Конец фильтра по времени открытия (необязательно)
- `page`: Номер страницы (отсчёт с 0, по умолчанию: 0)
- `size`: Элементов на странице (по умолчанию: 10)

**Возвращает:** protobuf `PositionsHistoryData` с:

- `history_positions`: Список PositionHistoryInfo с:

  - Тикет, символ, объём, тип
  - Время открытия, время закрытия
  - Цена открытия, цена закрытия
  - Прибыль, комиссия, своп
  - SL, TP

**Доступные типы сортировки:**

```python
AH_POSITION_OPEN_TIME_ASC       # Сначала самое раннее время открытия
AH_POSITION_OPEN_TIME_DESC      # Сначала самое недавнее время открытия
AH_POSITION_TICKET_ASC          # По тикету позиции по возрастанию
AH_POSITION_TICKET_DESC         # По тикету позиции по убыванию
```

**Технические детали:** Возвращает protobuf PositionsHistoryData. Каждый PositionHistoryInfo включает прибыль, комиссию, своп, времена и цены открытия/закрытия.

**Примечание:** Фильтрует по времени открытия позиции (не закрытия). Лучше, чем `get_order_history()`, для расчётов прибыли и анализа закрытых позиций.

## 🔗 Примеры использования

### Пример 1: Получение номеров тикетов (быстрый метод с реальной ценностью)

```python
async def list_open_tickets(service: MT5Service):
    """Get ticket numbers only (10-20x faster than full data)."""

    # Быстрый метод — только номера тикетов
    position_tickets, order_tickets = await service.get_opened_tickets()

    print(f"Open positions ({len(position_tickets)}):")
    for ticket in position_tickets:
        print(f"  Position #{ticket}")

    print(f"\nPending orders ({len(order_tickets)}):")
    for ticket in order_tickets:
        print(f"  Order #{ticket}")

    return position_tickets, order_tickets
```

### Пример 2: Получение полных деталей позиций

```python
from MetaRpcMT5 import mt5_term_api_account_helper_pb2 as account_helper_pb2

async def display_open_positions(service: MT5Service):
    """Get full details for all open positions and orders."""

    # Получаем полные данные (сортировка по времени открытия, сначала новые)
    data = await service.get_opened_orders(
        sort_mode=account_helper_pb2.BMT5_OPENED_ORDER_SORT_BY_OPEN_TIME_DESC
    )

    print("OPEN POSITIONS:")
    print("-" * 80)

    for pos in data.position_infos:
        print(f"Ticket: {pos.ticket}")
        print(f"  Symbol: {pos.symbol}")
        print(f"  Type: {'BUY' if pos.type == 0 else 'SELL'}")
        print(f"  Volume: {pos.volume}")
        print(f"  Open Price: {pos.price_open}")
        print(f"  Current Price: {pos.price_current}")
        print(f"  Profit: ${pos.profit:.2f}")
        print(f"  SL: {pos.stop_loss}, TP: {pos.take_profit}")
        print()

    print("\nPENDING ORDERS:")
    print("-" * 80)

    for order in data.opened_orders:
        print(f"Ticket: {order.ticket}")
        print(f"  Symbol: {order.symbol}")
        print(f"  Type: {order.type}")
        print(f"  Volume: {order.volume_current}")
        print(f"  Price: {order.price_open}")
        print(f"  SL: {order.stop_loss}, TP: {order.take_profit}")
        print()
```

### Пример 3: Получение закрытых позиций с P&L

```python
from datetime import datetime, timedelta
from MetaRpcMT5 import mt5_term_api_account_helper_pb2 as account_helper_pb2

async def analyze_closed_positions(service: MT5Service):
    """Analyze closed positions from last 30 days."""

    to_dt = datetime.now()
    from_dt = to_dt - timedelta(days=30)

    # Получаем историю позиций, отсортированную по времени открытия (сначала новые)
    history = await service.get_positions_history(
        sort_type=account_helper_pb2.AH_POSITION_OPEN_TIME_DESC,
        open_from=from_dt,
        open_to=to_dt,
        page=0,
        size=50
    )

    total_profit = 0.0
    wins = 0
    losses = 0

    print("CLOSED POSITIONS (Last 30 days):")
    print("-" * 80)

    for pos in history.history_positions:
        profit = pos.profit + pos.swap - pos.commission

        print(f"Ticket: {pos.ticket}")
        print(f"  Symbol: {pos.symbol}")
        print(f"  Type: {'BUY' if pos.type == 0 else 'SELL'}")
        print(f"  Volume: {pos.volume}")
        print(f"  Open: {pos.open_price} -> Close: {pos.close_price}")
        print(f"  Profit: ${pos.profit:.2f}")
        print(f"  Swap: ${pos.swap:.2f}")
        print(f"  Commission: ${pos.commission:.2f}")
        print(f"  Net P&L: ${profit:.2f}")
        print()

        total_profit += profit
        if profit > 0:
            wins += 1
        else:
            losses += 1

    # Статистика
    print("=" * 80)
    print(f"Total Trades: {wins + losses}")
    print(f"Wins: {wins}, Losses: {losses}")
    print(f"Win Rate: {wins / (wins + losses) * 100:.1f}%")
    print(f"Total P&L: ${total_profit:.2f}")
```

## Когда какой метод использовать

### Используйте get_opened_tickets()

**Используйте, когда:**

- Вам нужны только номера тикетов (не полные детали)
- Проверяете, существует ли конкретный тикет
- Подсчитываете позиции/ордера
- Отслеживаете новые позиции (опрос)
- Критична производительность

**Преимущество:** В 10-20 раз быстрее, чем `get_opened_orders()`

**Пример:**

```python
pos_tickets, order_tickets = await service.get_opened_tickets()
if 12345 in pos_tickets:
    print("Position exists")
```

---

### Используйте get_opened_orders()

**Используйте, когда:**

- Вам нужны полные детали позиции/ордера
- Отображаете информацию о позиции (прибыль, SL/TP, цены)
- Анализируете открытые сделки
- Строите дашборд

**Пример:**

```python
data = await service.get_opened_orders()
for pos in data.position_infos:
    print(f"{pos.symbol}: Profit ${pos.profit:.2f}")
```

---

### Используйте get_positions_total()

**Используйте, когда:**

- Быстрая проверка количества
- Простая проверка да/нет (есть ли открытые позиции?)
- Перед закрытием всех позиций

**Пример:**

```python
if await service.get_positions_total() == 0:
    print("All clear - no positions")
```

---

### Используйте get_order_history()

**Используйте, когда:**

- Анализируете историю исполнения ордеров
- Проверяете состояния ордеров (исполнен, отменён, отклонён)
- Просматриваете всю торговую активность (ордера + сделки)

**Пример:**

```python
history = await service.get_order_history(from_dt, to_dt)
```

---

### Используйте get_positions_history()

**Используйте, когда:**

- Рассчитываете торговую результативность (P&L)
- Анализируете только закрытые позиции
- Нужны детали прибыли/комиссии/свопа
- Строите торговый журнал

**Пример:**

```python
history = await service.get_positions_history(
    sort_type=account_helper_pb2.AH_POSITION_OPEN_TIME_DESC
)
```

## Рекомендации

1. **Для списков тикетов** - используйте `get_opened_tickets()` (преобразует protobuf repeated-поля в списки Python)
2. **Для отображения позиций** - используйте `get_opened_orders()` или вызывайте MT5Account напрямую (идентично)
3. **Для быстрого подсчёта** - используйте `get_positions_total()` или вызывайте MT5Account напрямую (идентично)
4. **Для анализа P&L** - используйте `get_positions_history()` или вызывайте MT5Account напрямую (идентично)
5. **Для отслеживания ордеров** - используйте `get_order_history()` или вызывайте MT5Account напрямую (идентично)

**Итог:** Только `get_opened_tickets()` добавляет ценность через преобразование списков. Остальные методы - сквозные; вызывайте MT5Account, если используете Service напрямую.

## Итог

**Реальная ценность для конечных пользователей:**

- ✅ `get_opened_tickets()` - Преобразует protobuf repeated-поля → списки Python (чище, чем ручное преобразование `list()`)
- ⚪ `get_positions_total()` - Простая распаковка (`data.total_positions`)

**Архитектурный слой (для MT5Sugar):**

- ⚪ `get_opened_orders()`, `get_order_history()`, `get_positions_history()` - Прямая передача в MT5Account
- Используется MT5Sugar для поддержания слоистой архитектуры (Sugar → Service → Account)
- Для прямого использования MT5Service: нет ценности, вызывайте MT5Account

**Ключевое отличие от методов символов:**

- Методы символов: MT5Account возвращает protobuf Data → Service распаковывает + преобразует → **реальная ценность**
- Методы позиций: MT5Account возвращает protobuf Data → Service в основном сквозной → **минимальная ценность**

**Рекомендация:**

- Используете **MT5Sugar**? Эти методы работают бесшовно через архитектуру
- Используете **MT5Service напрямую**? Используйте только `get_opened_tickets()` для более чистого преобразования списков. Для остальных операций вызывайте MT5Account.
