# MT5Service - Методы стриминга (API среднего уровня)

## ⚠️ Важно: Прочитайте сначала это

**MT5Service - это архитектурный слой** между высокоуровневым (Sugar) и низкоуровневым (Account) API.

### Понимание 5 методов стриминга:

| Метод | Ценность прямого использования | Архитектурная роль |
|--------|------------------|-------------------|
| `stream_ticks()` | ✅ **ВЫСОКАЯ** - Преобразует protobuf Timestamp → datetime + создаёт dataclass SymbolTick (8 полей) | ✅ Используется Sugar |
| `stream_trade_updates()` | ⚪ **НЕТ** - Прямая передача (`yield data`) без преобразования | ✅ Используется Sugar |
| `stream_position_profits()` | ⚪ **НЕТ** - Прямая передача (`yield data`) без преобразования | ✅ Используется Sugar |
| `stream_opened_tickets()` | ⚪ **НЕТ** - Прямая передача (`yield data`) без преобразования | ✅ Используется Sugar |
| `stream_transactions()` | ⚪ **НЕТ** - Прямая передача (`yield data`) без преобразования | ✅ Используется Sugar |

### Что это значит:

**Архитектура (3 слоя):**

```
MT5Sugar (ВЫСОКИЙ)     →  service.stream_ticks()          ← Sugar использует методы Service
MT5Service (СРЕДНИЙ)   →  account.on_symbol_tick()        ← Service преобразует datetime + создаёт dataclass
MT5Account (НИЗКИЙ)    →  gRPC-стрим → protobuf-объекты
```

**Разбивка по ценности:**

- ✅ **ВЫСОКАЯ** (1 метод): `stream_ticks()` - protobuf Timestamp → datetime + преобразование в dataclass SymbolTick
- ⚪ **НЕТ** (4 метода): Прямая передача - просто `yield data` со слоя Account

**Для прямого использования MT5Service:**

- ✅ **Используйте** `stream_ticks()` - избавляет вас от ручного преобразования Timestamp
- ⚪ **Опционально**: Остальные 4 метода - без преобразования, можно вызывать Account напрямую

**Для пользователей MT5Sugar:**

- ✅ Все методы работают безупречно - слой выполняет свою архитектурную задачу

---

**Слой API:** **СРЕДНИЙ УРОВЕНЬ** - обёртки над MT5Account с автоматическим преобразованием datetime

**Реализация:**

Эти методы реализованы в `src/pymt5/mt5_service.py`, который оборачивает низкоуровневый API `package/MetaRpcMT5/helpers/mt5_account.py` с преобразованием в dataclass и автоматическим переподключением.

**Файлы примеров:**

- `examples/2_service/05_service_streaming.py` - исчерпывающий демо-пример всех методов стриминга MT5Service

## Зачем эти методы существуют

### Реальная ценность: Смешанная обработка

**Только 1 метод добавляет ценность** через преобразование datetime + создание dataclass, **4 метода - прямая передача**:

**Проблема с MT5Account** (низкий уровень):

```python
# stream_ticks() — MT5Account возвращает protobuf с Timestamp
async for data in account.on_symbol_tick(["EURUSD"], None):
    # data.symbol_tick.time — это protobuf Timestamp, нужно ручное преобразование!
    tick_time = data.symbol_tick.time.ToDatetime()  # ← Ручное преобразование в datetime
    bid = data.symbol_tick.bid
    ask = data.symbol_tick.ask
    # ... ручное извлечение полей из protobuf

# Другие стримы — уже чистые protobuf-объекты:
async for data in account.on_trade(None):
    # data — это OnTradeData: type + event_data (сгруппированные коллекции) + account_info
    if data.HasField("event_data"):
        ed = data.event_data
        print(f"New positions: {len(ed.new_positions)}, new orders: {len(ed.new_orders)}")
```

**Решение с MT5Service** (средний уровень):

```python
# stream_ticks() — автоматическое преобразование datetime + dataclass:
async for tick in service.stream_ticks(["EURUSD"]):
    # tick — это dataclass SymbolTick с time уже в datetime!
    print(f"{tick.time}: Bid={tick.bid}, Ask={tick.ask}")
    # ✅ ЦЕННОСТЬ: ручной ToDatetime() не нужен, чистый dataclass

# Другие стримы — прямая передача (БЕЗ преобразования):
async for trade in service.stream_trade_updates():
    # ⚪ НЕТ ЦЕННОСТИ: тот же protobuf OnTradeData, что и на слое Account
    if trade.HasField("event_data"):
        ed = trade.event_data
        print(f"New positions: {len(ed.new_positions)}, new orders: {len(ed.new_orders)}")
```

**Что предоставляет MT5Service:**

1. **Преобразование datetime + dataclass** (1 метод ВЫСОКОЙ ценности):

   - `stream_ticks()`: Преобразует protobuf Timestamp → Python datetime + создаёт dataclass SymbolTick (8 полей)
   - Реализация: `tick_time = data.symbol_tick.time.ToDatetime()` + `yield SymbolTick(...)`

2. **Прямая передача** (4 метода БЕЗ ценности):

   - `stream_trade_updates()`: `async for data in account.on_trade(): yield data`
   - `stream_position_profits()`: `async for data in account.on_position_profit(): yield data`
   - `stream_opened_tickets()`: `async for data in account.on_positions_and_pending_orders_tickets(): yield data`
   - `stream_transactions()`: `async for data in account.on_trade_transaction(): yield data`
   - Они буквально просто пересылают protobuf-объекты без какой-либо обработки

3. **Авто-переподключение** (ВСЕ методы):

   - Все методы стриминга выигрывают от инфраструктуры `execute_stream_with_reconnect()`
   - Но это также доступно на слое Account

**Архитектурное назначение:**

- ✅ **MT5Sugar** использует эти методы для поддержания слоистой архитектуры (Sugar → Service → Account)
- ✅ **stream_ticks()** добавляет реальную ценность через преобразование datetime
- ⚪ **Остальные 4 метода** - только архитектурная согласованность, без обработки

## Все 5 методов стриминга

| Метод | Выдаёт | Описание |
|--------|--------|-------------|
| **`stream_ticks()`** | `SymbolTick` | Поток данных тиков в реальном времени (time авто-преобразуется) |
| **`stream_trade_updates()`** | `OnTradeData` | События сделок (новые/закрытые позиции) |
| **`stream_position_profits()`** | `OnPositionProfitData` | Обновления P&L позиций в реальном времени |
| **`stream_opened_tickets()`** | `OnPositionsAndPendingOrdersTicketsData` | Обновления тикетов позиций/ордеров (легковесно) |
| **`stream_transactions()`** | `OnTradeTransactionData` | Детальные события торговых транзакций |

## Ключевые концепции

### Асинхронные генераторы

Все методы стриминга являются **асинхронными генераторами** - используйте `async for` для итерации:

```python
async for item in service.stream_ticks(["EURUSD"]):
    print(item)  # Обрабатываем каждый тик по мере поступления
```

### Отмена

Используйте `cancellation_event` (asyncio.Event) для остановки стриминга:

```python
import asyncio

cancel_event = asyncio.Event()

async for tick in service.stream_ticks(["EURUSD"], cancel_event):
    print(tick)
    if some_condition:
        cancel_event.set()  # Остановить стриминг
```

### Автоматическое переподключение

Все методы стриминга используют `execute_stream_with_reconnect()` внутри - автоматическое переподключение при потере соединения!

## Сигнатуры методов

### 1) stream_ticks

```python
async def stream_ticks(
    self,
    symbols: List[str],
    cancellation_event: Optional[Any] = None,
) -> AsyncIterator[SymbolTick]
```

**Поток данных тиков в реальном времени.**

**Аргументы:**

- `symbols`: Список имён символов для стриминга (например, `["EURUSD", "GBPUSD"]`)
- `cancellation_event`: Необязательный asyncio.Event для остановки стрима

**Выдаёт:** dataclass `SymbolTick` с:

- `time`: **datetime** (уже преобразовано из protobuf Timestamp!)
- `bid`, `ask`, `last`: цены float
- `volume`, `time_ms`, `flags`, `volume_real`: детали тика

**Технические детали:** Низкий уровень стримит OnSymbolTickData с `symbol_tick.time` как protobuf Timestamp. Эта обёртка преобразует каждый Timestamp в Python datetime через `ToDatetime()` для каждого тика.

**Авто-переподключение:** Стрим продолжается до `cancellation_event.set()` или потери соединения (авто-переподключение через `execute_stream_with_reconnect`).

**Использование:**

```python
async for tick in service.stream_ticks(["EURUSD"]):
    print(f"{tick.time}: {tick.bid}/{tick.ask}")
```

### 2) stream_trade_updates

```python
async def stream_trade_updates(
    self,
    cancellation_event: Optional[Any] = None,
) -> AsyncIterator[Any]
```

**Поток событий сделок в реальном времени (новые/закрытые позиции).**

**Аргументы:**

- `cancellation_event`: Необязательный asyncio.Event для остановки стрима

**Выдаёт:** события protobuf `OnTradeData` с:

- `position_info`: Детали позиции при открытии/закрытии позиции
- `order_info`: Детали ордера при размещении/удалении отложенного ордера

**Технические детали:** Сервер отправляет OnTradeData, когда:

- Позиция открывается или закрывается
- Отложенный ордер размещён или удалён

Каждое событие несёт сгруппированную структуру `event_data`, содержащую коллекции изменений:
`new_orders`, `disappeared_orders`, `state_changed_orders`, `new_positions`,
`disappeared_positions`, `updated_positions`, плюс исторические ордера/сделки — каждая
repeated-список записей с полными деталями (ticket, symbol, volume, type и т. д.).

**Тонкая обёртка:** Пропускает protobuf OnTradeData без преобразования (минимальные накладные расходы).

**Использование:**

```python
async for trade in service.stream_trade_updates():
    print(f"Event type: {trade.type}")
    if trade.HasField("event_data"):
        ed = trade.event_data
        for pos in ed.new_positions:
            print(f"New position: {pos.ticket}")
        for order in ed.new_orders:
            print(f"New order: {order.ticket}")
```

### 3) stream_position_profits

```python
async def stream_position_profits(
    self,
    interval_ms: int = 1000,
    ignore_empty: bool = True,
    cancellation_event: Optional[Any] = None,
) -> AsyncIterator[Any]
```

**Поток обновлений прибыли позиций в реальном времени.**

**Аргументы:**

- `interval_ms`: Интервал опроса в миллисекундах (по умолчанию: 1000ms = 1 секунда)
- `ignore_empty`: Пропускать кадры без изменений (по умолчанию: True)
- `cancellation_event`: Необязательный asyncio.Event для остановки стрима

**Выдаёт:** protobuf `OnPositionProfitData` с:

- `new_positions`, `updated_positions`, `deleted_positions`: repeated-списки
  OnPositionProfitPositionInfo (`ticket`, `profit`, `position_symbol`)
- `account_info`: снимок баланса/средств/маржи/прибыли счёта

**Технические детали:** Сервер опрашивает позиции каждые `interval_ms` и отправляет обновления при изменении прибыли.

**ignore_empty=True** отфильтровывает кадры, где P&L позиций не изменялся, снижая трафик.

Каждый OnPositionProfitData группирует изменения в `new_positions` / `updated_positions` / `deleted_positions`.

**Использование:**

```python
async for profit_data in service.stream_position_profits(interval_ms=500):
    for pos in profit_data.updated_positions:
        print(f"Ticket {pos.ticket} ({pos.position_symbol}): ${pos.profit:.2f}")
```

### 4) stream_opened_tickets

```python
async def stream_opened_tickets(
    self,
    interval_ms: int = 1000,
    cancellation_event: Optional[Any] = None,
) -> AsyncIterator[Any]
```

**Поток обновлений тикетов позиций/ордеров в реальном времени (легковесно).**

**Аргументы:**

- `interval_ms`: Интервал опроса в миллисекундах (по умолчанию: 1000ms = 1 секунда)
- `cancellation_event`: Необязательный asyncio.Event для остановки стрима

**Выдаёт:** protobuf `OnPositionsAndPendingOrdersTicketsData` с:

- `position_tickets`: Список номеров тикетов позиций (repeated int64)
- `pending_order_tickets`: Список номеров тикетов отложенных ордеров (repeated int64)

**Технические детали:** Сервер опрашивает каждые `interval_ms` и отправляет OnPositionsAndPendingOrdersTicketsData.

**Преимущество:** В 10-20 раз меньше трафика, чем `stream_trade_updates()` - используйте, когда нужно отслеживать только изменения тикетов.

**Использование:**

```python
async for tickets in service.stream_opened_tickets(interval_ms=2000):
    print(f"Positions: {list(tickets.position_tickets)}")
    print(f"Orders: {list(tickets.pending_order_tickets)}")
```

### 5) stream_transactions

```python
async def stream_transactions(
    self,
    cancellation_event: Optional[Any] = None,
) -> AsyncIterator[Any]
```

**Поток торговых транзакций в реальном времени (детальный).**

**Аргументы:**

- `cancellation_event`: Необязательный asyncio.Event для остановки стрима

**Выдаёт:** события protobuf `OnTradeTransactionData` с:

- `type`: Тип группы событий
- `trade_transaction`: MqlTradeTransaction (его поле `type` - это тип транзакции — DEAL_ADD, ORDER_DELETE и т. д.)
- `trade_request`: MqlTradeRequest (исходный запрос)
- `trade_result`: MqlTradeResult (ответ брокера)

**Технические детали:** Сервер отправляет OnTradeTransactionData для каждого шага торговой операции (запрос → брокер → результат).

**Детальнее, чем stream_trade_updates():** Включает полный `trade_transaction` (с его типом транзакции), `trade_request` и `trade_result`.

**Тонкая обёртка:** Пропускает protobuf OnTradeTransactionData без преобразования.

**Использование:**

```python
async for transaction in service.stream_transactions():
    if transaction.HasField("trade_transaction"):
        tx = transaction.trade_transaction
        print(f"Transaction type: {tx.type}, order={tx.order_ticket}, deal={tx.deal_ticket}")
```

## 🔗 Примеры использования

### Пример 1: Стриминг тиков с авто-преобразованным datetime

```python
import asyncio
from pymt5 import MT5Service

async def stream_eurusd_ticks(service: MT5Service, duration_seconds: int = 60):
    """Stream EURUSD ticks for specified duration."""

    cancel_event = asyncio.Event()

    # Авто-остановка по истечении времени
    async def auto_stop():
        await asyncio.sleep(duration_seconds)
        cancel_event.set()

    asyncio.create_task(auto_stop())

    print(f"Streaming EURUSD ticks for {duration_seconds} seconds...")

    try:
        async for tick in service.stream_ticks(["EURUSD"], cancel_event):
            # tick.time уже datetime — преобразование не нужно!
            timestamp = tick.time.strftime('%H:%M:%S.%f')[:-3]
            spread = tick.ask - tick.bid

            print(f"[{timestamp}] Bid: {tick.bid:.5f} | "
                  f"Ask: {tick.ask:.5f} | "
                  f"Spread: {spread:.5f}")

    except asyncio.CancelledError:
        print("Stream cancelled")

    print("Streaming stopped")
```

### Пример 2: Мониторинг нескольких символов

```python
async def monitor_multiple_symbols(
    service: MT5Service,
    symbols: list,
    duration_seconds: int = 30
):
    """Stream ticks for multiple symbols simultaneously."""

    cancel_event = asyncio.Event()

    # Авто-остановка по истечении времени
    asyncio.create_task(auto_cancel(cancel_event, duration_seconds))

    print(f"Monitoring {len(symbols)} symbols: {', '.join(symbols)}")

    tick_counts = {symbol: 0 for symbol in symbols}

    async for tick in service.stream_ticks(symbols, cancel_event):
        # Отслеживаем, к какому символу относится этот тик
        # Примечание: у tick нет поля symbol, нужно отслеживать через подписку
        tick_counts[symbols[0]] += 1  # Упрощённо

        if tick_counts[symbols[0]] % 10 == 0:
            print(f"Received {tick_counts[symbols[0]]} ticks for {symbols[0]}")

    print(f"\nTotal ticks received: {sum(tick_counts.values())}")


async def auto_cancel(event, seconds):
    await asyncio.sleep(seconds)
    event.set()
```

### Пример 3: Обнаружение новых позиций через stream_trade_updates

```python
async def monitor_trades(service: MT5Service):
    """Monitor for new positions and closed positions."""

    print("Monitoring trade events (Ctrl+C to stop)...")

    try:
        async for trade in service.stream_trade_updates():
            if not trade.HasField("event_data"):
                continue
            ed = trade.event_data

            # Новые / изменённые позиции
            for pos in ed.new_positions:
                print(f"\nPOSITION UPDATE:")
                print(f"  Ticket: {pos.ticket}")
                print(f"  Type: {'BUY' if pos.type == 0 else 'SELL'}")
                print(f"  Volume: {pos.volume}")
                print(f"  Open price: {pos.price_open}")
                print(f"  Profit: ${pos.profit:.2f}")

            # Новые ордера
            for order in ed.new_orders:
                print(f"\nORDER UPDATE:")
                print(f"  Ticket: {order.ticket}")
                print(f"  State: {order.state}")
                print(f"  Current price: {order.price_current}")

    except KeyboardInterrupt:
        print("\nMonitoring stopped")
```

### Пример 4: Мониторинг P&L в реальном времени

```python
async def monitor_position_profits(
    service: MT5Service,
    update_interval_ms: int = 500
):
    """Monitor position profits in real-time."""

    print(f"Monitoring position profits (update every {update_interval_ms}ms)...")
    print("Press Ctrl+C to stop\n")

    total_profit = 0.0

    try:
        async for profit_data in service.stream_position_profits(
            interval_ms=update_interval_ms,
            ignore_empty=True  # Показывать только при изменении прибыли
        ):
            # Считаем суммарную прибыль по всем позициям
            current_total = 0.0

            print("\n" + "=" * 60)
            print("POSITION PROFITS:")
            print("-" * 60)

            for pos in profit_data.updated_positions:
                current_total += pos.profit
                print(f"Ticket #{pos.ticket} ({pos.position_symbol}): ${pos.profit:+.2f}")

            print("-" * 60)
            print(f"TOTAL PROFIT: ${current_total:+.2f}")

            # Оповещение о значительных изменениях
            if abs(current_total - total_profit) > 10.0:
                print("ALERT: Significant P&L change!")

            total_profit = current_total

    except KeyboardInterrupt:
        print("\n\nMonitoring stopped")
        print(f"Final total profit: ${total_profit:+.2f}")
```

### Пример 5: Легковесный мониторинг тикетов

```python
async def monitor_opened_tickets(service: MT5Service):
    """Monitor for new/closed positions using lightweight ticket stream."""

    known_position_tickets = set()
    known_order_tickets = set()

    print("Monitoring opened tickets (lightweight)...")

    try:
        async for tickets in service.stream_opened_tickets(interval_ms=1000):
            # Преобразуем в множества для удобного сравнения
            current_positions = set(tickets.position_tickets)
            current_orders = set(tickets.pending_order_tickets)

            # Обнаруживаем новые позиции
            new_positions = current_positions - known_position_tickets
            if new_positions:
                for ticket in new_positions:
                    print(f"NEW POSITION: #{ticket}")

            # Обнаруживаем закрытые позиции
            closed_positions = known_position_tickets - current_positions
            if closed_positions:
                for ticket in closed_positions:
                    print(f"CLOSED POSITION: #{ticket}")

            # Обнаруживаем новые отложенные ордера
            new_orders = current_orders - known_order_tickets
            if new_orders:
                for ticket in new_orders:
                    print(f"NEW ORDER: #{ticket}")

            # Обнаруживаем удалённые ордера
            deleted_orders = known_order_tickets - current_orders
            if deleted_orders:
                for ticket in deleted_orders:
                    print(f"DELETED ORDER: #{ticket}")

            # Обновляем известные тикеты
            known_position_tickets = current_positions
            known_order_tickets = current_orders

            # Показываем текущий статус
            print(f"[Status] Positions: {len(current_positions)}, "
                  f"Orders: {len(current_orders)}")

    except KeyboardInterrupt:
        print("\nMonitoring stopped")
```

### Пример 7: Комбинированный дашборд мониторинга

```python
import asyncio
from datetime import datetime

async def trading_dashboard(service: MT5Service):
    """Comprehensive trading dashboard with multiple streams."""

    cancel_event = asyncio.Event()

    # Задача 1: Мониторинг тиков
    async def tick_monitor():
        async for tick in service.stream_ticks(["EURUSD"], cancel_event):
            spread = tick.ask - tick.bid
            print(f"[TICK] {tick.time.strftime('%H:%M:%S')}: "
                  f"Bid={tick.bid:.5f}, Ask={tick.ask:.5f}, Spread={spread:.5f}")

    # Задача 2: Мониторинг сделок
    async def trade_monitor():
        async for trade in service.stream_trade_updates(cancel_event):
            if trade.HasField("event_data"):
                for pos in trade.event_data.new_positions:
                    print(f"[TRADE] Position {pos.ticket}: "
                          f"{'BUY' if pos.type == 0 else 'SELL'} {pos.volume} lots")

    # Задача 3: Мониторинг прибыли
    async def profit_monitor():
        async for profit_data in service.stream_position_profits(
            interval_ms=2000,
            ignore_empty=True,
            cancellation_event=cancel_event
        ):
            total = sum(p.profit for p in profit_data.updated_positions)
            print(f"[PROFIT] Total P&L: ${total:+.2f}")

    # Запускаем все мониторы параллельно
    print("Starting trading dashboard...")
    print("Press Ctrl+C to stop\n")

    try:
        await asyncio.gather(
            tick_monitor(),
            trade_monitor(),
            profit_monitor()
        )
    except KeyboardInterrupt:
        print("\n\nShutting down dashboard...")
        cancel_event.set()
        await asyncio.sleep(1)  # Даём стримам время закрыться

    print("Dashboard stopped")
```

## Когда какой метод использовать

### Используйте stream_ticks()

**Используйте, когда:**

- Нужны обновления цен в реальном времени
- Строите ценовые графики или индикаторы
- Отслеживаете движения рынка
- Важна точность времени

**Преимущество:** Time уже преобразовано в datetime!

**Пример:**

```python
async for tick in service.stream_ticks(["EURUSD"]):
    print(f"{tick.time}: {tick.bid}")
```

---

### Используйте stream_trade_updates()

**Используйте, когда:**

- Отслеживаете открытия/закрытия позиций
- Отслеживаете новые ордера
- Строите торговые уведомления
- Нужны полные детали позиции/ордера

**Пример:**

```python
async for trade in service.stream_trade_updates():
    if trade.HasField("event_data"):
        for pos in trade.event_data.new_positions:
            print(f"New position: {pos.ticket}")
```

---

### Используйте stream_position_profits()

**Используйте, когда:**

- Мониторинг P&L в реальном времени
- Автоматические триггеры стоп-лосса
- Оповещения о прибыли
- Строите дашборды P&L

**Пример:**

```python
async for profit_data in service.stream_position_profits():
    total = sum(p.profit for p in profit_data.updated_positions)
    if total < -100:
        print("ALERT: Large loss!")
```

---

### Используйте stream_opened_tickets()

**Используйте, когда:**

- Легковесный мониторинг позиций
- Нужны только номера тикетов (не полные детали)
- Ограничен трафик
- Высокочастотный мониторинг

**Преимущество:** В 10-20 раз меньше трафика, чем stream_trade_updates()

**Пример:**

```python
async for tickets in service.stream_opened_tickets():
    print(f"Open positions: {len(tickets.position_tickets)}")
```

---

### Используйте stream_transactions()

**Используйте, когда:**

- Нужна детальная история транзакций
- Отладка исполнения сделок
- Логирование всей торговой активности
- Построение контрольного следа (audit trail)

**Детальнее, чем stream_trade_updates()**

**Пример:**

```python
async for tx in service.stream_transactions():
    if tx.HasField("trade_transaction"):
        print(f"Transaction: {tx.trade_transaction.type}")
```

## Рекомендации

1. **Используйте cancellation_event** - Всегда предусматривайте способ корректной остановки стримов
2. **Обрабатывайте KeyboardInterrupt** - Используйте try/except для чистого завершения
3. **Не блокируйте цикл** - Обрабатывайте данные быстро в цикле async for
4. **Используйте stream_opened_tickets() для мониторинга** - в 10-20 раз эффективнее
5. **Используйте stream_ticks() для цен** - Time уже datetime!
6. **Задавайте подходящие интервалы** - Баланс между задержкой и производительностью
7. **Используйте ignore_empty=True** - Снижайте трафик для стриминга прибыли

**Шаблон отмены:**

```python
cancel_event = asyncio.Event()

try:
    async for item in service.stream_ticks(["EURUSD"], cancel_event):
        if should_stop:
            cancel_event.set()
except KeyboardInterrupt:
    cancel_event.set()
```

## Сравнение производительности

| Метод | Трафик | Частота обновлений | Сценарий использования |
|--------|-----------|------------------|----------|
| stream_ticks() | Высокий | Каждый тик | Мониторинг цен |
| stream_trade_updates() | Средний | По событию | Изменения позиций |
| stream_position_profits() | Низкий | Настраиваемая | Мониторинг P&L |
| stream_opened_tickets() | Очень низкий | Настраиваемая | Легковесный мониторинг |
| stream_transactions() | Высокий | Каждая транзакция | Детальное логирование |

**Лучше для мониторинга:** `stream_opened_tickets()` (очень низкий трафик, настраиваемый интервал)

**Лучше для цен:** `stream_ticks()` (реальное время, datetime авто-преобразуется)

**Лучше для P&L:** `stream_position_profits()` с `ignore_empty=True`

## Итог

### Оценка реальной ценности

**5 методов стриминга с минимальной обработкой** - только 1 добавляет ценность, 4 - прямая передача:

| Метод | Уровень ценности | Что он делает |
|--------|-------------|--------------|
| `stream_ticks()` | ✅ **ВЫСОКАЯ** | Преобразует protobuf Timestamp → datetime + создаёт dataclass SymbolTick (8 полей) |
| `stream_trade_updates()` | ⚪ **НЕТ** | Прямая передача: `async for data in account.on_trade(): yield data` |
| `stream_position_profits()` | ⚪ **НЕТ** | Прямая передача: `async for data in account.on_position_profit(): yield data` |
| `stream_opened_tickets()` | ⚪ **НЕТ** | Прямая передача: `async for data in account.on_positions_and_pending_orders_tickets(): yield data` |
| `stream_transactions()` | ⚪ **НЕТ** | Прямая передача: `async for data in account.on_trade_transaction(): yield data` |

**Почему эти методы имеют ценность (или нет):**

MT5Account стримит protobuf-объекты:
```python
# Низкоуровневые стримы:
async for data in account.on_symbol_tick(...):  # OnSymbolTickData с protobuf Timestamp
async for data in account.on_trade(...):  # protobuf OnTradeData (уже доступен)
async for data in account.on_position_profit(...):  # protobuf OnPositionProfitData (уже доступен)
```

Обработка в MT5Service:
```python
# Только stream_ticks() выполняет обработку:
async for tick in service.stream_ticks(...):
    # ✅ Преобразует: data.symbol_tick.time.ToDatetime() + dataclass SymbolTick

# Остальные 4 метода — без обработки:
async for trade in service.stream_trade_updates(...):
    # ⚪ Просто выдаёт: тот же protobuf OnTradeData со слоя Account
```

**Ключевые выводы:**

1. **Только 1 метод добавляет ценность** (stream_ticks):

   - Автоматическое преобразование datetime избавляет от ручного вызова `.ToDatetime()`
   - dataclass SymbolTick с 8 полями чище, чем доступ к protobuf
   - Реальное функциональное улучшение

2. **4 метода НЕ добавляют ценности** (прямая передача):

   - Буквально просто `async for data in account.method(): yield data`
   - Без преобразования, без обработки, без распаковки
   - Те же protobuf-объекты, что и на слое Account
   - Существуют только для архитектурной согласованности (нужны MT5Sugar)

3. **Все методы имеют авто-переподключение**:

   - Но это также доступно на слое Account через `execute_stream_with_reconnect()`

**Советы по производительности:**

- Используйте `stream_opened_tickets()` для частого мониторинга (очень эффективно - низкий трафик)
- Используйте `ignore_empty=True` для стриминга прибыли (снижение трафика)
- Задавайте подходящий `interval_ms` (баланс задержки и производительности)
- Всегда предоставляйте `cancellation_event` для корректного завершения

**Шаблон отмены:**

```python
cancel_event = asyncio.Event()
async for item in service.stream_ticks(symbols, cancel_event):
    if should_stop:
        cancel_event.set()
```

**Итог:**

- ✅ **Для прямых пользователей**: Только `stream_ticks()` добавляет ценность - остальные 4 метода могут вызывать Account напрямую
- ⚪ **Остальные 4 метода**: Без обработки - для них рассмотрите прямой вызов слоя Account
- ✅ **Для пользователей Sugar**: Все методы идеально выполняют архитектурную задачу
- ✅ **vs MT5Account**: Значительное улучшение только для stream_ticks() через преобразование datetime
