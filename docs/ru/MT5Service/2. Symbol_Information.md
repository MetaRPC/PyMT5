# ✅ MT5Service - Методы символов (API среднего уровня)

## Важно: Прочитайте сначала это

**MT5Service - это архитектурный слой** между высокоуровневым (Sugar) и низкоуровневым (Account) API.

### Понимание 13 методов:

| Метод | Ценность прямого использования | Архитектурная роль |
|--------|------------------|-------------------|
| `get_symbol_params_many()` | **ОЧЕНЬ ВЫСОКАЯ** - Агрегирует 17 полей + распаковывает список protobuf | Используется Sugar |
| `get_symbol_tick()` | **ВЫСОКАЯ** - Unix timestamp datetime + распаковывает 8 полей | Используется Sugar |
| `get_symbol_session_quote()` | **ВЫСОКАЯ** - 2x protobuf Timestamp datetime | Используется Sugar |
| `get_symbol_session_trade()` | **ВЫСОКАЯ** - 2x protobuf Timestamp datetime | Используется Sugar |
| `get_symbol_margin_rate()` | **СРЕДНЯЯ** - Распаковывает protobuf + создаёт dataclass | Используется Sugar |
| `get_symbols_total()` | **НИЗКАЯ** - Распаковывает `data.total` из protobuf | Используется Sugar |
| `symbol_exist()` | **НИЗКАЯ** - Распаковывает `(data.exists, data.is_custom)` | Используется Sugar |
| `get_symbol_name()` | **НИЗКАЯ** - Распаковывает `data.name` из protobuf | Используется Sugar |
| `symbol_select()` | **НИЗКАЯ** - Распаковывает `data.success` из protobuf | Используется Sugar |
| `is_symbol_synchronized()` | **НИЗКАЯ** - Распаковывает `data.synchronized` из protobuf | Используется Sugar |
| `get_symbol_double()` | **НИЗКАЯ** - Распаковывает `data.value` из protobuf | Используется Sugar |
| `get_symbol_integer()` | **НИЗКАЯ** - Распаковывает `data.value` из protobuf | Используется Sugar |
| `get_symbol_string()` | **НИЗКАЯ** - Распаковывает `data.value` из protobuf | Используется Sugar |

### Что это значит:

**🏗️ Архитектура (3 слоя):**
```
MT5Sugar (ВЫСОКИЙ)     service.get_symbol_tick()      Sugar использует методы Service
MT5Service (СРЕДНИЙ)   account.symbol_info_tick()     Service распаковывает protobuf + преобразует datetime
MT5Account (НИЗКИЙ)    gRPC-вызов protobuf Data
```

**Ключевое отличие от методов Account:**

- **ВСЕ методы символов имеют ценность** - MT5Account возвращает protobuf-объекты Data, которые требуют распаковки
- **Распаковка protobuf** - Service извлекает значения из `data.value`, `data.total` и т. д.
- **Преобразование datetime** - 3 метода преобразуют timestamps/protobuf Timestamps в Python datetime
- **Создание dataclass** - Более чистый API с типизированными dataclasses вместо сообщений protobuf

**Для прямого использования MT5Service:**

- **Используйте все методы** - все они добавляют ценность через распаковку protobuf
- **Методы высокой ценности** - `get_symbol_params_many()`, `get_symbol_tick()`, методы сессий
- **Методы низкой ценности** - простая распаковка, но всё же избавляют вас от ручного извлечения `data.value`

**Для пользователей MT5Sugar:**

- Все методы работают безупречно - слой выполняет свою архитектурную задачу

---

**Слой API:** **СРЕДНИЙ УРОВЕНЬ** - обёртки над MT5Account с нативными типами Python

**Реализация:**

Эти методы реализованы в `src/pymt5/mt5_service.py`, который оборачивает низкоуровневый API `package/MetaRpcMT5/helpers/mt5_account.py` удобными dataclasses и автоматическим преобразованием типов.

**Файлы примеров:**

- `examples/2_service/04_service_demo.py` - исчерпывающий демо-пример всех методов MT5Service, включая информацию о символах

## Зачем эти методы существуют

### Реальная ценность: Распаковка protobuf + преобразование datetime

**В отличие от методов Account**, методы символов в MT5Service **все добавляют реальную ценность**, потому что MT5Account возвращает protobuf-объекты Data:

**Проблема с MT5Account** (низкий уровень):
```python
# MT5Account возвращает protobuf-объекты Data — нужна ручная распаковка
data = await account.symbol_info_double(
    symbol="EURUSD",
    property=market_info_pb2.SYMBOL_BID
)
bid = data.value  # Ручное извлечение из protobuf-обёртки

# Время тика — это Unix timestamp, нужно ручное преобразование
tick_data = await account.symbol_info_tick("EURUSD")
tick_time = datetime.fromtimestamp(tick_data.time)  # Ручное преобразование в datetime
```

**Решение с MT5Service** (средний уровень):
```python
# Service распаковывает protobuf автоматически — возвращает нативные типы
bid = await service.get_symbol_double(
    symbol="EURUSD",
    property=market_info_pb2.SYMBOL_BID
)  # Уже float, а не protobuf Data!

# Тик с уже преобразованным datetime
tick = await service.get_symbol_tick("EURUSD")
print(tick.time)  # Уже объект datetime!
```

**Что предоставляет MT5Service:**

1. **Распаковка protobuf** (все 13 методов):

   - MT5Account: `return res.data` (объект protobuf)
   - MT5Service: `return data.value` (нативный тип Python)

2. **Преобразование datetime** (3 метода):

   - `get_symbol_tick()`: Unix timestamp `datetime.fromtimestamp()`
   - `get_symbol_session_quote()`: protobuf Timestamp `ToDatetime()` x2
   - `get_symbol_session_trade()`: protobuf Timestamp `ToDatetime()` x2

3. **Агрегация данных** (1 метод):

   - `get_symbol_params_many()`: 17 полей за один вызов вместо 17 отдельных вызовов

4. **Чистые dataclasses**:

   - `SymbolTick`, `SymbolParams`, `SessionTime`, `SymbolMarginRate` вместо сообщений protobuf

**Архитектурное назначение:**

- **MT5Sugar** использует эти методы для поддержания слоистой архитектуры (Sugar Service Account)
- **Прямые пользователи** тоже выигрывают - все методы добавляют ценность через распаковку и преобразование

## ➕ Dataclasses (DTO)

### SymbolTick

```python
@dataclass
class SymbolTick:
    """
    Current tick information for a symbol.

    ADVANTAGE: Time is already converted from Unix timestamp to datetime.
    """
    time: datetime          # Время тика (преобразовано из Unix timestamp)
    bid: float              # Текущая цена Bid
    ask: float              # Текущая цена Ask
    last: float             # Цена последней сделки
    volume: int             # Объём тика
    time_ms: int            # Время тика в миллисекундах
    flags: int              # Флаги тика
    volume_real: float      # Объём тика с десятичной точностью
```

### SymbolMarginRate

```python
@dataclass
class SymbolMarginRate:
    """Margin rate information for a symbol."""
    initial_margin_rate: float          # Начальная ставка маржи
    maintenance_margin_rate: float      # Требование поддерживающей маржи
```

### SessionTime

```python
@dataclass
class SessionTime:
    """Trading session time range."""
    from_time: datetime     # Время начала сессии (уже datetime)
    to_time: datetime       # Время окончания сессии (уже datetime)
```

### SymbolParams

```python
@dataclass
class SymbolParams:
    """
    Comprehensive symbol information.

    ADVANTAGE: All 17 important symbol parameters in one structure.
    Much more convenient than making multiple calls to SymbolInfoDouble/Integer/String.
    """
    name: str                   # Имя символа
    bid: float                  # Текущая цена Bid
    ask: float                  # Текущая цена Ask
    last: float                 # Цена последней сделки
    point: float                # Размер пункта (минимальное изменение цены)
    digits: int                 # Число знаков после запятой
    spread: int                 # Текущий спред в пунктах
    volume_min: float           # Минимальный объём для торговли
    volume_max: float           # Максимальный объём для торговли
    volume_step: float          # Шаг объёма
    trade_tick_size: float      # Размер тика для торговли
    trade_tick_value: float     # Стоимость тика для торговли
    trade_contract_size: float  # Размер контракта
    swap_long: float            # Своп для длинных позиций
    swap_short: float           # Своп для коротких позиций
    margin_initial: float       # Требование начальной маржи
    margin_maintenance: float   # Требование поддерживающей маржи
```

```python
async def get_symbol_params_many(
```

**Преимущество:** Гораздо быстрее, чем 17 отдельных вызовов SymbolInfoDouble/Integer/String на каждый символ!

## 🔗 Примеры использования

### Пример 1: Получение тика символа с авто-преобразованным временем

```python
async def monitor_tick(service: MT5Service, symbol: str):
    # Получаем тик — time уже datetime!
    tick = await service.get_symbol_tick(symbol)

    print(f"Symbol: {symbol}")
    print(f"Time: {tick.time.strftime('%Y-%m-%d %H:%M:%S')}")  # Уже datetime
    print(f"Bid: {tick.bid:.5f}")
    print(f"Ask: {tick.ask:.5f}")
    print(f"Last: {tick.last:.5f}")
    print(f"Volume: {tick.volume}")

    # Ручное преобразование timestamp не нужно!
```

### Пример 2: Проверка доступности символа

```python
async def check_symbol(service: MT5Service, symbol: str):
    exists, is_custom = await service.symbol_exist(symbol)

    if not exists:
        print(f"Symbol {symbol} does not exist")
        return False

    if is_custom:
        print(f"{symbol} is a custom symbol")

    # Проверяем синхронизацию
    synced = await service.is_symbol_synchronized(symbol)
    if not synced:
        print(f"WARNING: {symbol} data is not synchronized")
        return False

    print(f"{symbol} is available and synchronized")
    return True
```

### Пример 3: Получение времён торговой сессии

```python
from MetaRpcMT5 import mt5_term_api_market_info_pb2 as market_info_pb2

async def check_trading_hours(service: MT5Service, symbol: str):
    """Check if symbol is currently in trading session."""

    from datetime import datetime

    now = datetime.now()
    day_of_week = market_info_pb2.DayOfWeek.Value(
        f"DAY_{now.strftime('%A').upper()}"
    )

    try:
        # Получаем торговую сессию на сегодня (session_index=0 для основной сессии)

            day_of_week=day_of_week,
            session_index=0

        print(f"  From: {session.from_time.strftime('%H:%M:%S')}")
        print(f"  To: {session.to_time.strftime('%H:%M:%S')}")

        # Времена уже являются объектами datetime!
        if session.from_time <= now <= session.to_time:
            print("  Status: OPEN")
        else:
            print("  Status: CLOSED")

    except Exception as e:
        print(f"No trading session for {symbol} today: {e}")
```

```python
async def get_all_eur_symbols(service: MT5Service):
```

## Когда какой метод использовать

### Используйте get_symbol_tick()

**Используйте, когда:**
- Вам нужны текущие цены Bid/Ask с меткой времени
- Хотите получить полные данные тика за один вызов
- Нужно time как datetime (авто-преобразование)

**Пример:**
```python
tick = await service.get_symbol_tick("EURUSD")
print(f"Bid: {tick.bid}, Time: {tick.time}")
```

---

### Используйте get_symbol_double/integer/string()

**Используйте, когда:**
- Вам нужно ОДНО конкретное свойство
- Пишете проверки валидации
- Важна производительность (одно свойство быстрее, чем тик)

**Пример:**
```python
spread = await service.get_symbol_integer(
    "EURUSD", market_info_pb2.SYMBOL_SPREAD
)
```

---

### Используйте get_symbol_params_many()

**Используйте, когда:**
- Вам нужны данные для НЕСКОЛЬКИХ символов
- Строите сканер/скринер символов
- Нужна исчерпывающая информация о символе (17 полей)
- Хотите минимизировать число вызовов API

**Пример:**
```python
# Получаем все символы форекс сразу
symbols, _ = await service.get_symbol_params_many(name_filter="*USD")
```

**Преимущество:** В 100 раз быстрее отдельных вызовов для каждого символа!

## Рекомендации

1. **Для текущих цен + времени** - используйте `get_symbol_tick()` (Bid/Ask + datetime за один вызов, без ручной распаковки)
2. **Для нескольких символов** - используйте `get_symbol_params_many()` (17 полей на символ за один вызов - в 100 раз быстрее!)
3. **Для одного свойства** - используйте `get_symbol_double/integer/string()` (распаковывает protobuf `data.value` за вас)
4. **Для времён сессий** - используйте `get_symbol_session_quote/trade()` (преобразование datetime включено)
5. **Перед торговлей** - всегда проверяйте через `symbol_exist()` и `is_symbol_synchronized()` (чище, чем ручной protobuf)

**Итог:** Используйте MT5Service для всех операций с символами - он распаковывает protobuf-объекты Data и автоматически преобразует datetime.

## Итог

**Реальная ценность для конечных пользователей:**
- **ВСЕ 13 методов добавляют ценность** - MT5Account возвращает protobuf-объекты Data, которые требуют распаковки
- `get_symbol_params_many()` - Агрегирует 17 полей за один вызов (в 100 раз быстрее для нескольких символов)
- `get_symbol_tick()` - Unix timestamp datetime + распаковывает 8 полей
- `get_symbol_session_quote/trade()` - Protobuf Timestamps datetime x2
- Остальные 9 методов - Распаковка protobuf (`data.value` нативный тип)

**Архитектурный слой (для MT5Sugar):**
- Все методы используются MT5Sugar для поддержания слоистой архитектуры (Sugar Service Account)
- Предоставляют единый интерфейс с согласованным именованием (префикс `get_*`)

**Ключевое отличие от методов Account:**
- Методы Account: MT5Account уже возвращает нативные типы Service не добавляет ценности (просто передача)
- Методы символов: MT5Account возвращает protobuf Data Service распаковывает + преобразует **реальная ценность**

**Рекомендация:**
- Используете **MT5Sugar**? Эти методы работают бесшовно через архитектуру
- Используете **MT5Service напрямую**? Все методы добавляют ценность - используйте их все!
  - **Высокий приоритет**: `get_symbol_params_many()`, `get_symbol_tick()`, методы сессий
  - **Средний приоритет**: Остальные методы избавляют вас от ручной распаковки protobuf
