# MT5Service - Методы торговых операций (API среднего уровня)

## ⚠️ Важно: Прочитайте сначала это

**MT5Service - это архитектурный слой** между высокоуровневым (Sugar) и низкоуровневым (Account) API.

### Понимание 6 методов:

| Метод | Ценность прямого использования | Архитектурная роль |
|--------|------------------|-------------------|
| `check_order()` | ✅ **ОЧЕНЬ ВЫСОКАЯ** - Извлекает глубоко вложенный protobuf → dataclass OrderCheckResult (8 полей) | ✅ Используется Sugar |
| `place_order()` | ✅ **ВЫСОКАЯ** - Уплощает protobuf → dataclass OrderResult (10 полей) | ✅ Используется Sugar |
| `modify_order()` | ✅ **ВЫСОКАЯ** - Уплощает protobuf → dataclass OrderResult (10 полей) | ✅ Используется Sugar |
| `close_order()` | ⚪ **НИЗКАЯ** - Распаковывает `data.returned_code` из protobuf → int | ✅ Используется Sugar |
| `calculate_margin()` | ⚪ **НИЗКАЯ** - Распаковывает `data.margin` из protobuf → float | ✅ Используется Sugar |
| `calculate_profit()` | ⚪ **НИЗКАЯ** - Распаковывает `data.profit` из protobuf → float | ✅ Используется Sugar |

### Что это значит:

**Архитектура (3 слоя):**

```
MT5Sugar (ВЫСОКИЙ)     →  service.place_order()           ← Sugar использует методы Service
MT5Service (СРЕДНИЙ)   →  account.order_send()            ← Service распаковывает protobuf + создаёт dataclasses
MT5Account (НИЗКИЙ)    →  gRPC-вызов → protobuf-объекты Data
```

**Разбивка по ценности:**

- ✅ **ОЧЕНЬ ВЫСОКАЯ** (1 метод): `check_order()` - извлекает глубоко вложенную структуру `mql_trade_check_result`
- ✅ **ВЫСОКАЯ** (2 метода): `place_order()`, `modify_order()` - уплощают 10 полей protobuf в чистый dataclass
- ⚪ **НИЗКАЯ** (3 метода): Простая распаковка одного поля protobuf (`returned_code`, `margin`, `profit`)

**Для прямого использования MT5Service:**

- ✅ **Настоятельно рекомендуется**: Используйте `check_order()`, `place_order()`, `modify_order()` - значительная ценность преобразования в dataclass
- ⚪ **Опционально**: `close_order()`, `calculate_margin()`, `calculate_profit()` - незначительная ценность распаковки

**Для пользователей MT5Sugar:**

- ✅ Все методы работают безупречно - слой выполняет свою архитектурную задачу

---

**Слой API:** **СРЕДНИЙ УРОВЕНЬ** - обёртки над MT5Account с чистым возвратом dataclass

**Реализация:**

Эти методы реализованы в `src/pymt5/mt5_service.py`, который оборачивает низкоуровневый API `package/MetaRpcMT5/helpers/mt5_account.py` с преобразованием в dataclass для торговых результатов.

**Файлы примеров:**

- `examples/2_service/04_service_demo.py` - исчерпывающий демо-пример всех методов MT5Service, включая торговые операции (STEP 5)

## Зачем эти методы существуют

### Реальная ценность: Распаковка protobuf + преобразование в dataclass

**3 метода добавляют ОЧЕНЬ ВЫСОКУЮ/ВЫСОКУЮ ценность** через сложное преобразование в dataclass, **3 метода добавляют НИЗКУЮ ценность** через простую распаковку:

**Проблема с MT5Account** (низкий уровень):

```python
# MT5Account возвращает сложные protobuf-объекты
request = trading_helper_pb2.OrderSendRequest()
request.symbol = "EURUSD"
request.volume = 0.1
request.operation = trading_helper_pb2.TMT5_ORDER_TYPE_BUY  # тип/направление ордера

result_data = await account.order_send(request, None, None)
# result_data — это protobuf OrderSendData с 10 вложенными полями
if result_data.returned_code == 10009:  # TRADE_RETCODE_DONE
    print(f"Deal: {result_data.deal}, Order: {result_data.order}")
    # Нужно вручную обращаться к каждому из 10 полей protobuf

# Проверка ордера требует извлечения ГЛУБОКО ВЛОЖЕННОЙ структуры:
check_response = await account.order_check(request, None, None)
result = check_response.mql_trade_check_result  # ← Глубоко вложено!
if result.returned_code == 0:
    print(f"Valid! Margin: {result.margin}")
```

**Решение с MT5Service** (средний уровень):

```python
# Service создаёт чистые dataclasses — без ручного извлечения полей
request = trading_helper_pb2.OrderSendRequest()
request.symbol = "EURUSD"
request.volume = 0.1
request.operation = trading_helper_pb2.TMT5_ORDER_TYPE_BUY

result = await service.place_order(request)
# result — это dataclass OrderResult с 10 понятными полями
if result.returned_code == 10009:
    print(f"Deal: {result.deal}, Order: {result.order}")
    # Доступ через чистый dataclass с подсказками типов

# Проверка ордера возвращает чистый dataclass — без вложенности:
check = await service.check_order(request)
# check — это dataclass OrderCheckResult с 8 полями — уже извлечены!
if check.returned_code == 0:
    print(f"Valid! Margin: {check.margin}")
```

**Что предоставляет MT5Service:**

1. **Сложное преобразование в dataclass** (3 метода ВЫСОКОЙ/ОЧЕНЬ ВЫСОКОЙ ценности):

   - `check_order()`: Извлекает глубоко вложенный `mql_trade_check_result` → OrderCheckResult (8 полей)
   - `place_order()`: Уплощает 10 полей protobuf → dataclass OrderResult
   - `modify_order()`: Уплощает 10 полей protobuf → dataclass OrderResult

2. **Простая распаковка** (3 метода НИЗКОЙ ценности):

   - `close_order()`: Распаковывает `data.returned_code` → int
   - `calculate_margin()`: Распаковывает `data.margin` → float
   - `calculate_profit()`: Распаковывает `data.profit` → float

3. **Более чистый API**:

   - Нет нужды вручную обращаться к вложенным структурам protobuf
   - Подсказки типов для автодополнения в IDE
   - Понятные имена полей в dataclasses

**Архитектурное назначение:**

- ✅ **MT5Sugar** использует эти методы для поддержания слоистой архитектуры (Sugar → Service → Account)
- ✅ **Прямые пользователи** существенно выигрывают от преобразования в dataclass (особенно check_order/place_order/modify_order)

## Все 6 методов

| Метод | Возвращает | Описание |
|--------|---------|-------------|
| **`place_order()`** | `OrderResult` | Отправить рыночный/отложенный ордер брокеру |
| **`modify_order()`** | `OrderResult` | Изменить существующий ордер или позицию (SL/TP) |

| **`calculate_profit()`** | `float` | Рассчитать потенциальную прибыль по сделке |

## Ключевые концепции

### Типы ордеров

- **Рыночный ордер**: Исполняется немедленно по текущей рыночной цене (BUY/SELL)
- **Отложенный ордер**: Исполняется, когда цена достигает заданного уровня (BUY_LIMIT, SELL_LIMIT, BUY_STOP, SELL_STOP)

### Коды возврата

Все торговые операции возвращают **код возврата**, указывающий на успех/неудачу:

- **10009 (TRADE_RETCODE_DONE)**: Успех - ордер размещён/изменён/закрыт
- **10004 (TRADE_RETCODE_REQUOTE)**: Реквота - цена изменилась, повторите
- **10006 (TRADE_RETCODE_REJECT)**: Отклонено брокером
- **10007 (TRADE_RETCODE_CANCEL)**: Отменено трейдером
- **10013 (TRADE_RETCODE_INVALID_VOLUME)**: Недопустимый объём
- **10014 (TRADE_RETCODE_INVALID_PRICE)**: Недопустимая цена
- **10015 (TRADE_RETCODE_INVALID_STOPS)**: Недопустимые SL/TP

**Всегда проверяйте returned_code == 10009 для успеха!**

### Предторговая валидация

Перед отправкой ордеров используйте `check_order()` для валидации:
- Достаточная маржа
- Корректные объём/цена/стопы
- Торговля разрешена

## ➕ Dataclasses (DTO)

### OrderResult

```python
@dataclass
class OrderResult:
    """
    Result of a trading operation.

    ADVANTAGE: Clean dataclass instead of protobuf OrderSendData/OrderModifyData.
    """
    returned_code: int      # Код возврата операции (10009 = TRADE_RETCODE_DONE)
    deal: int               # Номер тикета сделки (если исполнена)
    order: int              # Номер тикета ордера (если размещён)
    volume: float           # Исполненный объём, подтверждённый брокером
    price: float            # Цена исполнения, подтверждённая брокером
    bid: float              # Текущая цена Bid
    ask: float              # Текущая цена Ask
    comment: str            # Комментарий брокера или описание ошибки
    request_id: int         # ID запроса, установленный терминалом
    ret_code_external: int  # Внешний код возврата
```

**Использование:**

```python
result = await service.place_order(request)
if result.returned_code == 10009:
    print(f"Success! Deal: {result.deal}, Order: {result.order}")
else:
    print(f"Failed: {result.comment}")
```

```python
@dataclass
class OrderCheckResult:
    """Result of order validation."""
```

## Сигнатуры методов

### 1) place_order

```python
async def place_order(
    self,
    request: Any,  # trading_helper_pb2.OrderSendRequest
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[Any] = None,
) -> OrderResult
```

**Отправить рыночный/отложенный ордер брокеру.**

**Аргументы:**

- `request`: protobuf OrderSendRequest с параметрами ордера

**Возвращает:** dataclass `OrderResult` с тикетами сделки/ордера и деталями исполнения

**Технические детали:** Низкий уровень возвращает protobuf OrderSendData с вложенными полями ответа брокера. Эта обёртка уплощает protobuf в dataclass OrderResult с 10 полями.

**Проверяйте returned_code == 10009 (TRADE_RETCODE_DONE) для успешного исполнения.**

**Поля OrderSendRequest:**

```python
request.symbol = "EURUSD"           # Символ
request.operation = 0               # TMT5_ORDER_TYPE_BUY (тип/направление ордера)
request.volume = 0.1                # Объём в лотах
request.price = 0.0                 # 0 для рыночных ордеров
request.stop_loss = 1.08000         # Стоп-лосс (необязательно)
request.take_profit = 1.09000       # Тейк-профит (необязательно)
request.slippage = 20               # Макс. отклонение цены в пунктах
request.comment = "My order"        # Необязательный комментарий
```

## 🔗 Примеры использования

### Пример 1: Размещение рыночного ордера на покупку

```python
from pymt5 import MT5Service
from MetaRpcMT5 import mt5_term_api_trading_helper_pb2 as trading_helper_pb2

async def place_market_buy(service: MT5Service, symbol: str, volume: float):
    """Place a market BUY order."""

    # Создаём запрос
    request = trading_helper_pb2.OrderSendRequest()
    request.symbol = symbol
    request.volume = volume
    request.operation = trading_helper_pb2.TMT5_ORDER_TYPE_BUY  # рыночная покупка
    request.price = 0.0             # 0 для рыночных ордеров
    request.slippage = 20           # Макс. отклонение 20 пунктов
    request.comment = "Market BUY"

    # Отправляем ордер
    result = await service.place_order(request)

    # Проверяем результат
    if result.returned_code == 10009:  # TRADE_RETCODE_DONE
        print(f"SUCCESS!")
        print(f"  Deal: {result.deal}")
        print(f"  Order: {result.order}")
        print(f"  Price: {result.price}")
        print(f"  Volume: {result.volume}")
    else:
        print(f"FAILED: {result.comment}")
        print(f"  Return code: {result.returned_code}")

    return result
```

### Пример 3: Валидация ордера перед размещением

```python
from MetaRpcMT5 import mt5_term_api_trade_functions_pb2 as trade_functions_pb2

async def safe_place_order(
    service: MT5Service,
    symbol: str,
    volume: float
) -> bool:
    """Validate order before placing."""

    # Шаг 1: Проверка ордера
    check_request = trade_functions_pb2.OrderCheckRequest()
    check_request.mql_trade_request.symbol = symbol
    check_request.mql_trade_request.volume = volume
    check_request.mql_trade_request.action = trade_functions_pb2.TRADE_ACTION_DEAL
    check_request.mql_trade_request.order_type = trade_functions_pb2.ORDER_TYPE_TF_BUY
    check_request.mql_trade_request.price = 0.0

    check_result = await service.check_order(check_request)

    if check_result.returned_code != 0:
        print(f"Order validation FAILED: {check_result.comment}")
        return False

    print("Order validation PASSED:")
    print(f"  Required margin: ${check_result.margin:.2f}")
    print(f"  Free margin after: ${check_result.margin_free:.2f}")
    print(f"  Margin level after: {check_result.margin_level:.2f}%")

    # Шаг 2: Размещение ордера
    order_request = trading_helper_pb2.OrderSendRequest()
    order_request.symbol = symbol
    order_request.volume = volume
    order_request.operation = trading_helper_pb2.TMT5_ORDER_TYPE_BUY
    order_request.price = 0.0
    order_request.slippage = 20

    result = await service.place_order(order_request)

    if result.returned_code == 10009:
```

### Пример 8: Полный безопасный торговый поток

```python
async def safe_trade_with_validation(
    service: MT5Service,
    symbol: str,
    volume: float,
    sl_points: int,
    tp_points: int
):
    """Complete safe trading flow with all validations."""

    from MetaRpcMT5 import mt5_term_api_market_info_pb2 as market_info_pb2

    # Шаг 1: Получаем текущую цену
    tick = await service.get_symbol_tick(symbol)
    print(f"Current price: {tick.ask}")

    # Шаг 2: Рассчитываем цены SL/TP
    point = await service.get_symbol_double(
        symbol, market_info_pb2.SYMBOL_POINT
    )
    sl = tick.ask - (sl_points * point)
    tp = tick.ask + (tp_points * point)

    print(f"Calculated SL: {sl:.5f}, TP: {tp:.5f}")

    # Шаг 3: Рассчитываем требуемую маржу
    margin_request = trade_functions_pb2.OrderCalcMarginRequest()
    margin_request.symbol = symbol
    margin_request.volume = volume
    margin_request.order_type = trade_functions_pb2.ORDER_TYPE_TF_BUY
    margin_request.open_price = tick.ask

    required_margin = await service.calculate_margin(margin_request)
    print(f"Required margin: ${required_margin:.2f}")

    # Шаг 4: Проверяем свободную маржу
    from MetaRpcMT5 import mt5_term_api_account_information_pb2 as account_info_pb2
    free_margin = await service.get_account_double(
        account_info_pb2.ACCOUNT_MARGIN_FREE
    )

    if free_margin < required_margin:
        print(f"INSUFFICIENT MARGIN: Need ${required_margin:.2f}, have ${free_margin:.2f}")
        return None

    # Шаг 5: Рассчитываем потенциальную прибыль
    profit_request = trade_functions_pb2.OrderCalcProfitRequest()
    profit_request.symbol = symbol
    profit_request.volume = volume
    profit_request.order_type = trade_functions_pb2.ORDER_TYPE_TF_BUY
    profit_request.open_price = tick.ask
    profit_request.close_price = tp

    potential_profit = await service.calculate_profit(profit_request)
    print(f"Potential TP profit: ${potential_profit:.2f}")

    # Шаг 6: Валидируем ордер
    check_request = trade_functions_pb2.OrderCheckRequest()
    check_request.mql_trade_request.symbol = symbol
    check_request.mql_trade_request.volume = volume
    check_request.mql_trade_request.action = trade_functions_pb2.TRADE_ACTION_DEAL
    check_request.mql_trade_request.order_type = trade_functions_pb2.ORDER_TYPE_TF_BUY
    check_request.mql_trade_request.price = 0.0

    check_result = await service.check_order(check_request)

    if check_result.returned_code != 0:
        print(f"Order validation failed: {check_result.comment}")
        return None

    print("Order validation passed!")

    # Шаг 7: Размещаем ордер
    order_request = trading_helper_pb2.OrderSendRequest()
    order_request.symbol = symbol
    order_request.volume = volume
    order_request.operation = trading_helper_pb2.TMT5_ORDER_TYPE_BUY
    order_request.price = 0.0
    order_request.stop_loss = sl
    order_request.take_profit = tp
    order_request.slippage = 20
    order_request.comment = "Safe validated order"

    result = await service.place_order(order_request)

    if result.returned_code == 10009:
        print(f"\nSUCCESS! Order placed:")
        print(f"  Ticket: {result.order}")
        print(f"  Price: {result.price}")
        print(f"  SL: {sl:.5f}, TP: {tp:.5f}")
        return result
    else:
        print(f"\nFAILED: {result.comment}")
        return None
```

## Когда какой метод использовать

### Используйте place_order()

**Используйте, когда:**

- Открываете новые позиции (рыночные или отложенные ордера)
- Нужно указать SL/TP вместе с ордером
- Готовы отправить ордер брокеру

**Важно:**

- Всегда проверяйте `returned_code == 10009` для успеха
- Сначала используйте `check_order()` для валидации

---

### Используйте modify_order()

**Используйте, когда:**

- Меняете SL/TP на открытой позиции
- Изменяете цену отложенного ордера
- Корректируете стопы в зависимости от рыночных условий

---

### Используйте close_order()

**Используйте, когда:**

- Закрываете открытую позицию
- Удаляете отложенный ордер
- Экстренный выход из сделки

---

### Используйте check_order()

**Используйте, когда:**

- Предварительно валидируете ордер перед размещением
- Проверяете требования к марже
- Смотрите влияние на счёт перед торговлей

**ВСЕГДА используйте перед place_order() для безопасности!**

---

### Используйте calculate_margin()

**Используйте, когда:**

- Планируете размер позиции
- Проверяете, достаточно ли у вас маржи
- Рассчитываете максимальный размер позиции

---

### Используйте calculate_profit()

**Используйте, когда:**

- Рассчитываете соотношение риск/доходность
- Устанавливаете цели TP
- Анализируете потенциал сделки

## Рекомендации

1. **Всегда сначала валидируйте** - Используйте `check_order()` перед `place_order()`
2. **Проверяйте коды возврата** - `returned_code == 10009` означает успех

## Итог

### Оценка реальной ценности

**6 методов со смешанными уровнями ценности** - 3 с ВЫСОКОЙ/ОЧЕНЬ ВЫСОКОЙ ценностью (преобразование в dataclass), 3 с НИЗКОЙ ценностью (простая распаковка):

| Метод | Уровень ценности | Что он делает |
|--------|-------------|--------------|
| `check_order()` | ✅ **ОЧЕНЬ ВЫСОКАЯ** | Извлекает глубоко вложенный `mql_trade_check_result` → OrderCheckResult (8 полей) |
| `place_order()` | ✅ **ВЫСОКАЯ** | Уплощает 10 полей protobuf → dataclass OrderResult |
| `modify_order()` | ✅ **ВЫСОКАЯ** | Уплощает 10 полей protobuf → dataclass OrderResult |
| `close_order()` | ⚪ **НИЗКАЯ** | Распаковывает `data.returned_code` из protobuf → int |
| `calculate_margin()` | ⚪ **НИЗКАЯ** | Распаковывает `data.margin` из protobuf → float |
| `calculate_profit()` | ⚪ **НИЗКАЯ** | Распаковывает `data.profit` из protobuf → float |

**Почему эти методы имеют ценность:**

MT5Account возвращает protobuf-объекты:
```python
# Низкий уровень возвращает:
result_data: OrderSendData = await account.order_send(...)  # 10 полей protobuf
check_response: OrderCheckResponse = await account.order_check(...)  # Глубоко вложено!
close_data: OrderCloseData = await account.order_close(...)  # обёртка data.returned_code
margin_response: OrderCalcMarginResponse = await account.order_calc_margin(...)  # data.margin
```

MT5Service распаковывает и преобразует:
```python
# Средний уровень возвращает:
result: OrderResult = await service.place_order(...)              # Уплощённый dataclass (10 полей)
check: OrderCheckResult = await service.check_order(...)          # Извлечённый dataclass (8 полей)
code: int = await service.close_order(...)                        # Распакованный int
margin: float = await service.calculate_margin(...)               # Распакованный float
```

**Ключевые преимущества:**

1. **Сложное преобразование в dataclass** (ВЫСОКАЯ/ОЧЕНЬ ВЫСОКАЯ ценность):

   - `check_order()` - Извлекает глубоко вложенную структуру protobuf (ОЧЕНЬ ценно!)
   - `place_order()`, `modify_order()` - Уплощают 10 полей в чистый dataclass OrderResult

2. **Простая распаковка** (НИЗКАЯ ценность):

   - `close_order()`, `calculate_margin()`, `calculate_profit()` - Простое извлечение одного поля

3. **Подсказки типов** - Полная поддержка автодополнения в IDE для всех полей dataclass

4. **Понятные коды возврата** - Все методы возвращают стандартизированные коды для обработки ошибок

**Лучшие практики:**

1. ✅ **ВСЕГДА используйте** `check_order()` перед `place_order()` для безопасности - он извлекает сложные данные валидации
2. ✅ **ВСЕГДА проверяйте** `returned_code == 10009` для успеха
3. ✅ **ВСЕГДА рассчитывайте** маржу перед торговлей
4. ✅ **ВСЕГДА используйте** стоп-лосс и тейк-профит
5. ✅ **ВСЕГДА обрабатывайте** ошибки (проверяйте `result.comment`)

**Итог:**

- ✅ **Для прямых пользователей**: Настоятельно рекомендуем использовать `check_order()`, `place_order()`, `modify_order()` - значительная ценность преобразования в dataclass
- ⚪ **Опционально**: `close_order()`, `calculate_margin()`, `calculate_profit()` - незначительная распаковка, можно вызывать Account напрямую
- ✅ **Для пользователей Sugar**: Методы идеально выполняют архитектурную задачу
- ✅ **vs MT5Account**: Значительное улучшение через преобразование в dataclass, особенно для check_order()
