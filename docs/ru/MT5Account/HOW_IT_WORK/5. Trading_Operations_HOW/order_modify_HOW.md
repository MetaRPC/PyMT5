## order_modify — Как это работает

---

## 📌 Обзор

Этот пример показывает, как использовать низкоуровневый метод `order_modify()` для **изменения параметров уже существующего ордера**, в частности — **изменения цены входа отложенного ордера**.

Важно понимать:

* ордер **уже существует**
* у него есть `ticket`
* метод **не создаёт новый ордер**
* метод **не открывает позицию**

Он используется, когда нужно адаптировать ранее размещённый ордер к текущей рыночной ситуации.

---

## Сигнатура метода

```python
async def order_modify(
    request: OrderModifyRequest,
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[asyncio.Event] = None,
) -> OrderModifyData
```

Ключевые моменты:

* метод асинхронный
* выполняет реальное торговое действие
* работает с существующим ордером по `ticket`
* изменяет **только явно указанные параметры**

---

## 🧩 Пример кода — Изменение цены отложенного ордера

```python
# Получить текущую цену инструмента
tick_data = await account.symbol_info_tick("EURUSD")
current_bid = tick_data.bid

# Рассчитать новую цену (15 пунктов ниже рынка)
pip_size = 0.0001
new_price = current_bid - (15 * pip_size)

# Сформировать запрос на изменение ордера
request = OrderModifyRequest(
    ticket=789012,      # тикет существующего отложенного ордера
    stop_loss=0,        # SL не меняется
    take_profit=0,      # TP не меняется
    price=new_price     # новая цена входа
)

result = await account.order_modify(request)
```

---

## 🟢 Подробное объяснение

---

### 1️⃣ Получение текущей рыночной цены

```python
tick_data = await account.symbol_info_tick("EURUSD")
current_bid = tick_data.bid
```

На этом шаге:

* запрашивается последний тик по символу
* используется текущая цена Bid
* API возвращает только рыночные данные, без торговой логики

Цена используется как основа для расчёта новой цены ордера.

---

### 2️⃣ Расчёт новой цены для отложенного ордера

```python
new_price = current_bid - (15 * pip_size)
```

Это пользовательская торговая логика:

* ордер смещается ниже текущей цены
* типичный сценарий для BUY LIMIT
* величина смещения (15 пунктов) задаётся стратегией

API не участвует в этом шаге.

---

### 3️⃣ Формирование OrderModifyRequest

```python
request = OrderModifyRequest(
    ticket=789012,
    stop_loss=0,
    take_profit=0,
    price=new_price
)
```

Ключевые моменты:

* `ticket` — идентификатор изменяемого ордера
* **изменяется только параметр `price`**
* параметры SL и TP явно указаны как неизменяемые

Метод `order_modify()` не делает предположений и не изменяет параметры, которые не были переданы.

---

### 4️⃣ Отправка команды изменения

```python
result = await account.order_modify(request)
```

На этой стадии:

* торговая команда отправляется на сервер
* сервер проверяет корректность новой цены
* учитываются ограничения брокера и торговые правила

Ордер либо изменяется, либо операция отклоняется.

---

### 5️⃣ Результат операции

Ответ содержит:

* код исполнения операции
* описание результата
* обновлённую информацию об ордере

Результат **должен быть проверен** пользовательским кодом.

---

## Роль низкоуровневого метода

Чёткая граница ответственности:

**`order_modify()`**:

* принимает запрос на изменение ордера
* пытается применить изменения на сервере
* возвращает технический результат
* не рассчитывает торговую логику

**Пользовательский код**:

* решает, когда и зачем менять ордер
* рассчитывает новую цену
* выбирает параметры для изменения
* анализирует результат операции

---

## Итог

Метод `order_modify()` используется для **точного изменения параметров существующего ордера**.

Корректный паттерн использования:

> **получить рыночные данные → рассчитать новые параметры → отправить изменение → проверить результат**

Это ключевой инструмент для динамического управления отложенными ордерами в автоматизированных торговых стратегиях.
