## order_send — Как это работает

---

## 📌 Обзор

Этот пример показывает, как использовать низкоуровневый метод `order_send()` для **фактической отправки торгового ордера** на сервер с обработкой результата и логикой повторных попыток.

Метод `order_send()` — ключевая точка всей торговой цепочки:

* до него выполняются расчёты и проверки
* после него состояние счёта может измениться

Именно здесь торговое решение превращается в действие.

---

## Сигнатура метода

```python
async def order_send(
    request: OrderSendRequest,
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[asyncio.Event] = None,
) -> OrderSendData
```

Ключевые моменты:

* метод асинхронный
* выполняет реальную торговую операцию
* отправляет ордер на сервер
* возвращает результат исполнения

---

## 🧩 Пример кода — Ордер с логикой повторных попыток

```python
request = OrderSendRequest(
    symbol="EURUSD",
    operation=ORDER_TYPE_BUY,
    volume=0.01,
    price=0,
    slippage=20,
    comment="Order with retry",
    expert_id=12345
)

max_retries = 3
retry_delay = 1.0

for attempt in range(1, max_retries + 1):
    print(f"[ATTEMPT {attempt}/{max_retries}]")

    result = await account.order_send(request)

    if result.returned_code == 10009:
        print(f"[SUCCESS] Order executed on attempt {attempt}")
        print(f"Deal: #{result.deal}, Price: {result.price}")
        break
    else:
        print(f"[FAILED] Code: {result.returned_code}")
        print(f"Reason: {result.returned_code_description}")

        if attempt < max_retries:
            await asyncio.sleep(retry_delay)
```

## 🟢 Подробное объяснение

---

### 1️⃣ Формирование торгового запроса

```python
request = OrderSendRequest(...)
```

На этой стадии:

* формируется полный торговый ордер
* указываются все необходимые параметры
* запрос полностью описывает будущую сделку

Это тот же объект, что используется в реальной торговле.

---

### 2️⃣ Отправка ордера на сервер

```python
result = await account.order_send(request)
```

При каждом вызове:

* запрос отправляется на торговый сервер
* сервер пытается исполнить ордер
* возвращается результат исполнения

Важно: отсутствие исключения **не означает успеха**.

---

### 3️⃣ Проверка результата исполнения

```python
result.returned_code
```

Код возврата определяет исход операции:

* `10009` — ордер успешно исполнен
* любое другое значение — отказ

Дополнительно сервер возвращает:

* номер сделки (`deal`)
* цену исполнения (`price`)
* текстовое описание причины отказа

---

### 4️⃣ Логика повторных попыток

```python
for attempt in range(...)
```

Логика повторных попыток реализуется **полностью в пользовательском коде**:

* API не повторяет попытки автоматически
* пользователь решает, сколько раз пробовать
* между попытками выдерживается пауза

Это позволяет адаптироваться к изменяющимся рыночным условиям.

---

### 5️⃣ Завершение цикла

Цикл завершается:

* при успешном исполнении ордера
* или после исчерпания всех попыток

В обоих случаях пользовательский код точно знает исход операции.

---

## Роль низкоуровневого метода

Чёткая граница ответственности:

**`order_send()`**:

* отправляет торговый ордер
* пытается исполнить его на сервере
* возвращает технический результат
* не гарантирует успех
* не повторяет попытки

**Пользовательский код**:

* формирует торговое решение
* определяет стратегию повторных попыток
* анализирует результат
* управляет риском повторных отправок

---

## Итог

Метод `order_send()` — финальный шаг торговой цепочки:

> **расчёт → валидация → отправка → результат**

Корректное использование всегда подразумевает:

* проверку `returned_code`
* обработку отказов
* осознанное управление повторными попытками

Такой подход делает торговые системы надёжными и предсказуемыми в реальных рыночных условиях.
