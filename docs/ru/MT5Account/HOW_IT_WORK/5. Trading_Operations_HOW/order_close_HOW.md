## order_close — Как это работает

---

## 📌 Обзор

Этот пример показывает, как использовать низкоуровневый метод `order_close()` для **фактического закрытия уже открытой торговой позиции**.

В отличие от методов расчёта и валидации, `order_close()` инициирует **реальную торговую операцию**, которая:

* изменяет состояние счёта
* закрывает позицию
* фиксирует финансовый результат

Метод используется, когда позиция уже существует и известен её `ticket`.

---

## Сигнатура метода

```python
async def order_close(
    request: OrderCloseRequest,
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[asyncio.Event] = None,
) -> OrderCloseData
```

Ключевые моменты:

* метод асинхронный
* выполняет торговую операцию
* работает с конкретным тикетом
* возвращает результат исполнения

---

## 🧩 Пример кода — Закрытие всей позиции

```python
request = OrderCloseRequest(
    ticket=123456,
    volume=0,        # 0 = закрыть позицию полностью
    slippage=20      # максимально допустимое проскальзывание
)

result = await account.order_close(request)

if result.returned_code == 10009:
    print("[SUCCESS] Position closed")
else:
    print(f"[FAILED] Code: {result.returned_code}")
    print(f"Description: {result.returned_code_description}")
```

## 🟢 Подробное объяснение

---

### 1️⃣ Указание тикета позиции

```python
ticket=123456
```

Тикет однозначно идентифицирует позицию:

* метод не ищет позицию автоматически
* не проверяет её существование заранее
* ответственность за корректность тикета лежит на пользователе

Если тикет некорректен — сервер вернёт ошибку.

---

### 2️⃣ Полное закрытие позиции через `volume = 0`

```python
volume=0
```

Особенность параметра:

* `0` означает **закрыть позицию полностью**
* сервер сам определяет текущий объём позиции
* не нужно знать фактический размер

Если указать `volume > 0`, будет выполнено **частичное закрытие**.

---

### 3️⃣ Контроль проскальзывания

```python
slippage=20
```

Этот параметр задаёт:

* максимально допустимое отклонение цены
* защиту от невыгодного исполнения
* торговое ограничение, а не логику API

Если цена вышла за допустимый диапазон — закрытие может быть отклонено.

---

### 4️⃣ Выполнение торговой операции

```python
result = await account.order_close(request)
```

На этой стадии:

* торговая команда отправляется на сервер
* происходит попытка закрыть позицию по рынку
* состояние счёта может измениться

Это **небезопасная операция** в том смысле, что она влияет на торговый результат.

---

### 5️⃣ Проверка результата исполнения

```python
result.returned_code
```

Код возврата определяет исход операции:

* `10009` — успешное исполнение
* любое другое значение — отказ

Дополнительно возвращается текстовое описание причины отказа.

Проверка результата — обязательная часть корректного использования метода.

---

## Роль низкоуровневого метода

Чёткая граница ответственности:

**`order_close()`**:

* отправляет команду закрытия позиции
* пытается исполнить её на сервере
* возвращает технический результат

**Пользовательский код**:

* выбирает позицию для закрытия
* определяет объём закрытия
* задаёт допустимое проскальзывание
* анализирует результат
* принимает дальнейшие решения

---

## Итог

Метод `order_close()` используется для **явного и контролируемого закрытия позиций**.

Корректный паттерн использования:

> **сформировать запрос → отправить → проверить результат → действовать дальше**

Это базовый строительный блок для систем автоматической торговли, управления рисками и стратегий выхода из рынка.
