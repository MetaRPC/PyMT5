## on_symbol_tick — Как это работает

---

## 📌 Обзор

`on_symbol_tick()` — это низкоуровневый стриминговый метод, предназначенный для получения **сырых тиковых данных в реальном времени** для одного или нескольких символов.

Метод предоставляет доступ к каждому рыночному тику (bid / ask), но **не выполняет никаких расчётов и не хранит состояние**. Все производные метрики, аналитика и торговая логика реализуются исключительно на стороне пользователя.

В этом примере поток тиков используется для **сбора статистики спреда bid-ask** за фиксированный период времени.

---

## Сигнатура метода

```python
async def on_symbol_tick(
    symbols: list[str],
    cancellation_event: Optional[asyncio.Event] = None,
):
    -> AsyncIterator[OnSymbolTickData]
```

Ключевые особенности:

* асинхронный стриминговый метод (`async for`)
* возвращает поток тиковых обновлений
* не имеет встроенного механизма остановки
* время жизни полностью контролируется пользователем

---

## 🧩 Пример кода — Отслеживание статистики спреда bid-ask

```python
import asyncio
from collections import defaultdict
from MetaRpcMT5 import MT5Account

async def track_spread_stats():
    account = MT5Account(
        user=12345,
        password="password",
        grpc_server="mt5.mrpc.pro:443"
    )

    await account.connect_by_server_name(
        server_name="YourBroker-Demo",
        base_chart_symbol="EURUSD"
    )

    spreads = defaultdict(list)
    cancel_event = asyncio.Event()

    async def stop_after(seconds: int):
        await asyncio.sleep(seconds)
        cancel_event.set()

    try:
        asyncio.create_task(stop_after(60))

        symbols = ["EURUSD", "GBPUSD"]

        async for tick_data in account.on_symbol_tick(
            symbols=symbols,
            cancellation_event=cancel_event
        ):
            tick = tick_data.symbol_tick
            spread = tick.ask - tick.bid
            spreads[tick.symbol].append(spread)

        print("\n=== Spread Statistics ===")
        for symbol, values in spreads.items():
            avg_spread = sum(values) / len(values)
            print(f"\n{symbol}:")
            print(f"  Ticks received: {len(values)}")
            print(f"  Average spread: {avg_spread * 10000:.1f} pips")
            print(f"  Min spread: {min(values) * 10000:.1f} pips")
            print(f"  Max spread: {max(values) * 10000:.1f} pips")

    finally:
        await account.channel.close()

asyncio.run(track_spread_stats())
```

## 🟢 Подробное объяснение

---

### 1️⃣ Подготовка хранилища данных

```python
spreads = defaultdict(list)
```

Создаётся структура для накопления пользовательских данных:

* ключ — имя торгового символа
* значение — список записанных значений спреда

Метод `on_symbol_tick()` **не агрегирует и не хранит историю**, поэтому вся статистика собирается вручную.

---

### 2️⃣ Управление временем жизни потока

```python
cancel_event = asyncio.Event()
```

Поток не имеет встроенного механизма завершения.

Время жизни потока полностью контролируется пользователем через `cancellation_event`.

---

### 3️⃣ Завершение по таймеру через асинхронную корутину

```python
async def stop_after(seconds: int):
    await asyncio.sleep(seconds)
    cancel_event.set()
```

Вспомогательная корутина:

* выполняется параллельно с обработкой тиков
* ждёт заданный интервал времени
* корректно завершает поток без исключений

---

### 4️⃣ Подписка на поток тиков

```python
async for tick_data in account.on_symbol_tick(
    symbols=symbols,
    cancellation_event=cancel_event
):
```

На этой стадии:

* создаётся подписка для указанных символов
* сервер начинает присылать тиковые обновления
* каждая итерация цикла соответствует одному рыночному тику

Метод возвращает **поток событий**, а не состояние рынка.

---

### 5️⃣ Обработка тиков на стороне пользователя

```python
spread = tick.ask - tick.bid
spreads[tick.symbol].append(spread)
```

Здесь выполняется вся бизнес-логика:

* расчёт производных значений
* агрегация данных
* подготовка аналитики

API выступает в этом процессе исключительно источником данных.

---

### 6️⃣ Завершение потока и постобработка

После установки `cancel_event`:

* поток данных корректно завершается
* пользовательский код переходит к анализу
* выполняются все необходимые расчёты

---

### 7️⃣ Постобработка и вывод статистики

```python
print("\n=== Spread Statistics ===")
for symbol, values in spreads.items():
    avg_spread = sum(values) / len(values)
    print(f"\n{symbol}:")
    print(f"  Ticks received: {len(values)}")
    print(f"  Average spread: {avg_spread * 10000:.1f} pips")
    print(f"  Min spread: {min(values) * 10000:.1f} pips")
    print(f"  Max spread: {max(values) * 10000:.1f} pips")
```

На этой стадии поток уже завершён, и код работает **исключительно с накопленными данными**.

Здесь выполняется следующее:

* перебор всех символов, по которым были получены тики
* анализ собранных значений спреда
* расчёт агрегированных метрик

---

#### Количество полученных тиков

```python
len(values)
```

Показывает:

* сколько рыночных событий было получено
* фактическую плотность потока
* косвенную оценку ликвидности символа за выбранный период

---

#### Средний спред

```python
avg_spread = sum(values) / len(values)
```

Среднее значение рассчитывается **после завершения потока**:

* API не предоставляет готовых агрегатов
* расчёты выполняются на стороне пользователя
* формула может быть изменена под любые требования

Перевод в пункты:

```python
avg_spread * 10000
```

— это пользовательское соглашение, а не часть API.

---

#### Минимальный и максимальный спред

```python
min(values)
max(values)
```

Позволяет:

* оценить диапазон колебаний спреда
* выявить экстремальные значения
* сравнить поведение разных символов

---

## Итоговая модель ответственности

**`on_symbol_tick()`**:

* поставляет сырые рыночные события
* не интерпретирует данные
* не управляет временем жизни
* не хранит историю

**Пользовательский код**:

* управляет подпиской
* определяет длительность обработки
* рассчитывает метрики
* строит аналитику или стратегии

---

## Итог

Этот пример иллюстрирует паттерн стриминга сырых данных:

**подписаться → получать сырые тики → накапливать данные → рассчитывать статистику**

Ключевые моменты:

* `on_symbol_tick()` поставляет сырые рыночные тики (bid/ask), а не производные метрики
* каждый тик — это атомарное рыночное событие
* пользовательский код отвечает за:
  * хранение истории тиков
  * расчёт производных значений (спред, средние, min/max)
  * определение времени жизни потока
  * постобработку накопленных данных

API выступает исключительно источником данных, тогда как вся аналитика, агрегация и интерпретация полностью остаются на стороне пользователя.
