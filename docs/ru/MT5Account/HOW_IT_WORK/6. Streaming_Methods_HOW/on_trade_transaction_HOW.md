## on_trade_transaction — Как это работает

---

## 📌 Обзор

`on_trade_transaction()` — это низкоуровневый стриминговый метод для получения **атомарных торговых транзакций** в реальном времени.

Каждая транзакция отражает **одно конкретное торговое действие или переход состояния**, например:

* появление ордера
* изменение состояния ордера
* исполнение
* закрытие

В отличие от агрегированных торговых потоков, этот метод предназначен для **аудита, отладки и восстановления полной истории событий**.

В этом примере `on_trade_transaction()` используется для **отслеживания жизненного цикла ордеров**, записывая все их состояния по `order_ticket`.

---

## Сигнатура метода

```python
async def on_trade_transaction(
    cancellation_event: Optional[asyncio.Event] = None,
):
    -> AsyncIterator[OnTradeTransactionData]
```

Ключевые особенности:

* асинхронный поток (`async for`)
* возвращает атомарные торговые транзакции
* не агрегирует события
* не хранит историю
* предназначен для детального анализа торговых процессов

---

## 🧩 Пример кода — Трекер жизненного цикла ордеров

```python
import asyncio
from MetaRpcMT5 import MT5Account

async def track_order_lifecycle():
    account = MT5Account(
        user=12345,
        password="password",
        grpc_server="mt5.mrpc.pro:443"
    )
    await account.connect_by_server_name(
        server_name="YourBroker-Demo",
        base_chart_symbol="EURUSD"
    )

    order_states = {}  # тикет ордера -> список состояний

    try:
        async for tx_data in account.on_trade_transaction():
            tx = tx_data.trade_transaction

            if tx.order_ticket > 0:
                if tx.order_ticket not in order_states:
                    order_states[tx.order_ticket] = []

                order_states[tx.order_ticket].append({
                    'state': tx.order_state,
                    'type': tx.type,
                    'price': tx.price,
                    'volume': tx.volume
                })

                print(f"\n[LIFECYCLE] Order #{tx.order_ticket}:")
                for i, state in enumerate(order_states[tx.order_ticket], 1):
                    print(f"   {i}. State: {state['state']}, "
                          f"Type: {state['type']}, "
                          f"Price: {state['price']}")

    except KeyboardInterrupt:
        print("\nStopping lifecycle tracker...")
        print(f"\nTracked {len(order_states)} orders")

    finally:
        await account.channel.close()

asyncio.run(track_order_lifecycle())
```

## 🟢 Подробное объяснение

---

### 1️⃣ Подписка на поток торговых транзакций

```python
async for tx_data in account.on_trade_transaction():
```

Создаётся подписка на низкоуровневый торговый поток:

* сервер присылает каждую торговую транзакцию
* события поступают по мере их возникновения
* поток не агрегирует и не фильтрует данные

Каждая итерация цикла — это **одно атомарное событие**.

---

### 2️⃣ Извлечение транзакции

```python
tx = tx_data.trade_transaction
```

`trade_transaction` описывает одно торговое действие и содержит:

* идентификатор ордера (`order_ticket`)
* текущее состояние ордера (`order_state`)
* тип операции
* цену и объём

Это минимальная единица торговой истории.

---

### 3️⃣ Фильтрация транзакций ордеров

```python
if tx.order_ticket > 0:
```

Не каждая торговая транзакция относится к ордерам.

Фильтрация позволяет:

* исключить служебные и нерелевантные события
* сосредоточиться на жизненном цикле ордера
* не смешивать разные типы торговых сущностей

---

### 4️⃣ Инициализация истории ордера

```python
if tx.order_ticket not in order_states:
    order_states[tx.order_ticket] = []
```

При первом появлении `order_ticket`:

* создаётся новая запись
* начинается сбор истории состояний
* последующие события добавляются последовательно

---

### 5️⃣ Запись состояния ордера

```python
order_states[tx.order_ticket].append({...})
```

Каждая транзакция сохраняется как шаг жизненного цикла:

* состояние ордера
* тип операции
* параметры сделки

Метод `on_trade_transaction()` не хранит историю — это ответственность пользователя.

---

### 6️⃣ Восстановление жизненного цикла

```python
for i, state in enumerate(order_states[tx.order_ticket], 1):
```

История ордера полностью отображается при каждом новом событии:

* видна последовательность переходов
* удобно для анализа поведения ордера
* полезно для диагностики и аудита

Это диагностический приём, а не обязательный паттерн.

---

### 7️⃣ Завершение потока

В этом примере поток выполняется бесконечно:

* завершение выполняется вручную (`Ctrl+C`)
* `KeyboardInterrupt` перехватывается
* соединение корректно закрывается

---

## Итоговая модель ответственности

**`on_trade_transaction()`**:

* поставляет атомарные торговые транзакции
* отражает каждый шаг торгового процесса
* не агрегирует и не интерпретирует события
* не хранит историю

**Пользовательский код**:

* группирует транзакции
* восстанавливает жизненные циклы
* выполняет аудит и анализ
* строит диагностические инструменты

---

## Итог

Этот пример иллюстрирует паттерн event sourcing на уровне транзакций:

**подписаться → получать атомарные события → группировать по сущности → восстанавливать жизненный цикл**

Ключевые моменты:

* `on_trade_transaction()` поставляет атомарные торговые события, а не агрегированное состояние
* каждое событие представляет один шаг торгового процесса
* пользовательский код отвечает за:
  * группировку событий (по `order_ticket`)
  * сохранение их порядка
  * восстановление смысла более высокого уровня (жизненный цикл ордера)

API выступает исключительно источником фактов, тогда как вся интерпретация, построение истории и анализ полностью остаются на стороне пользователя.
