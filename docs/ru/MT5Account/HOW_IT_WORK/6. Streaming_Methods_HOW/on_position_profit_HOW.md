## on_position_profit — Как это работает

---

## 📌 Обзор

Этот пример показывает, как использовать низкоуровневый стриминговый метод `on_position_profit()` для **реакции на изменения прибыли открытых позиций в реальном времени** и выполнения автоматических торговых действий при выполнении заданного условия.

В данном случае реализуется логический тейк-профит:

> если прибыль позиции достигает заданного значения — позиция автоматически закрывается.

Важно: это **не серверный TP**, а пользовательская логика, построенная поверх потока обновлений.

---

## Сигнатура метода

```python
async def on_position_profit(
    interval_ms: int,
    ignore_empty: bool = True,
    cancellation_event: Optional[asyncio.Event] = None,
):
    -> AsyncIterator[OnPositionProfitData]
```

Ключевые моменты:

* метод асинхронный и стриминговый (`async for`)
* работает во времени, а не как однократный вызов
* возвращает **обновления**, а не полный снимок состояния
* не принимает торговых решений

---

## 🧩 Пример кода — Автоматический тейк-профит по целевой прибыли

```python
async for update in account.on_position_profit(
    interval_ms=500,
    ignore_empty=True
):
    for pos in update.updated_positions:
        if pos.profit >= target_profit:
            close_req = OrderCloseRequest(
                ticket=pos.ticket,
                volume=0,
                slippage=20,
                comment="Auto TP"
            )

            result = await account.order_close(close_req)

            if result.returned_code == 10009:
                print(f"[SUCCESS] Position #{pos.ticket} closed")
            else:
                print(f"[FAILED] Code: {result.returned_code}")
                print(f"Description: {result.returned_code_description}")
```

## 🟢 Подробное объяснение

---

### 1️⃣ Подписка на поток обновлений прибыли

```python
async for update in account.on_position_profit(...):
```

На этой стадии:

* создаётся подписка на обновления прибыли
* сервер периодически присылает данные
* цикл выполняется до явной остановки

Это **поток**, а не обычный запрос.

---

### 2️⃣ Интервал обновления

```python
interval_ms=500
```

Параметр задаёт:

* частоту опроса сервера
* баланс между свежестью и нагрузкой

Метод работает не «по рыночному событию», а с заданным интервалом.

---

### 3️⃣ Фильтрация пустых обновлений

```python
ignore_empty=True
```

При включении:

* кадры без изменений пропускаются
* пользовательский код получает только значимые события

Это упрощает обработку и снижает шум.

---

### 4️⃣ Работа только с изменившимися позициями

```python
for pos in update.updated_positions:
```

Важно:

* не все позиции приходят в каждом обновлении
* только те, чья прибыль изменилась
* это типичный событийно-ориентированный паттерн

---

### 5️⃣ Проверка пользовательского условия

```python
if pos.profit >= target_profit:
```

Здесь выполняется **пользовательская бизнес-логика**:

* API не знает, что такое целевая прибыль
* API не сравнивает значения
* API лишь сообщает факты

---

### 6️⃣ Инициирование торгового действия

```python
result = await account.order_close(close_req)
```

При выполнении условия:

* отправляется команда закрытия позиции
* состояние счёта может измениться
* выполняется реальная торговая операция

---

### 7️⃣ Проверка результата закрытия

```python
if result.returned_code == 10009:
```

Даже автоматическое закрытие:

* по умолчанию не считается успешным
* требует проверки результата (код 10009 = успешное исполнение)
* может быть отклонено сервером

---

## Роль низкоуровневого метода

Чёткая граница ответственности:

**`on_position_profit()`**:

* поставляет поток обновлений прибыли
* не принимает решений
* не закрывает позиции

**`order_close()`**:

* выполняет торговое действие
* пытается закрыть позицию
* возвращает результат

**Пользовательский код**:

* задаёт целевую прибыль
* принимает решение о закрытии
* связывает событие и действие

---

## Архитектурный паттерн

Этот пример иллюстрирует фундаментальный паттерн:

> **поток → условие → действие**

Или в терминах торговой стратегии:

> **наблюдение → триггер → исполнение**

---

## Итог

Метод `on_position_profit()` предназначен для **реактивного контроля состояния позиций**.

Он позволяет строить собственные стратегии управления:

* тейк-профит
* логика трейлинга
* выходы на основе риска

оставаясь при этом строго низкоуровневым источником данных, а не механизмом принятия решений.
