## market_book_release — Как это работает

---

## 📌 Обзор

Метод `market_book_release()` предназначен для **явного завершения работы со стаканом цен (Depth of Market, DOM)** по символу.

Он существует не для получения данных или анализа рынка, а для **корректного управления жизненным циклом DOM как ресурса**.

Этот метод должен вызываться **всегда**, когда работа со стаканом завершена.

---

## Зачем существует market_book_release

DOM — это **не одноразовый запрос**, а активный ресурс:

* он открывается вызовом `market_book_add()`
* поддерживается сервером и терминалом
* потребляет ресурсы
* существует во времени

`market_book_release()` нужен, чтобы **явно сообщить системе**, что:

> «Этот стакан больше не нужен, ресурсы можно освободить»

Без этого вызова DOM считается активным.

---

## Сигнатура метода

```python
async def market_book_release(
    symbol: str,
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[asyncio.Event] = None,
):
```

Ключевые моменты:

* метод асинхронный
* работает в рамках уже установленного соединения
* не возвращает рыночные данные
* не закрывает соединение с сервером

---

## 🧩 Пример кода — Гарантированная отписка через контекстный менеджер

```python
from contextlib import asynccontextmanager

@asynccontextmanager
async def dom_subscription(account, symbol):
    try:
        result = await account.market_book_add(symbol)
        if not result.opened_successfully:
            raise Exception(f"Failed to subscribe to {symbol} DOM")

        print(f"[SUBSCRIBED] {symbol} DOM")
        yield
    finally:
        await account.market_book_release(symbol)
        print(f"[RELEASED] {symbol} DOM")
```

Этот пример демонстрирует корректный паттерн использования `market_book_release()`.

## 🟢 Подробное объяснение

---

### 1️⃣ Открытие DOM

```python
await account.market_book_add(symbol)
```

DOM переводится в активное состояние:

* терминал начинает поддерживать стакан цен
* данные становятся доступны через `market_book_get()`

---

### 2️⃣ Работа со стаканом внутри контекста

```python
yield
```

В этом блоке:

* DOM гарантированно открыт
* можно безопасно запрашивать его состояние
* пользовательский код может завершиться любым способом

---

### 3️⃣ Автоматическая отписка

```python
await account.market_book_release(symbol)
```

Этот код выполняется **всегда**:

* при нормальном выходе
* при `return`
* при исключении

Это ключевая гарантия корректного освобождения ресурсов.

---

## Что market_book_release делает и чего НЕ делает

**Делает:**

* закрывает DOM для символа
* освобождает ресурсы терминала и сервера
* завершает подписку на стакан

**НЕ делает:**

* не закрывает соединение
* не завершает торговую сессию
* не влияет на другие символы
* не возвращает данные

---

## Роль низкоуровневого метода

Чёткая граница ответственности:

**`market_book_release()`**:

* управляет жизненным циклом DOM
* завершает работу с ресурсом

**Пользовательский код**:

* решает, когда DOM больше не нужен
* гарантирует вызов release
* определяет архитектуру (try/finally, контекстный менеджер и т. д.)

---

## Итог

Метод `market_book_release()` создан для одной конкретной цели:

> **явно и безопасно завершить работу со стаканом**

Он не является опциональным и должен рассматриваться как **обязательный шаг** в любой работе с DOM.

Корректный паттерн использования:

> **открыть DOM → работать → всегда освобождать ресурс**
