## symbol_params_many — Как это работает

---

## 📌 Обзор

Этот пример показывает, как использовать низкоуровневый асинхронный метод `symbol_params_many()` для получения **параметров всех символов** с помощью постраничной загрузки.

Метод `symbol_params_many()` предназначен для пакетного получения информации сразу по нескольким символам. Поскольку количество символов может быть большим, API использует **постраничную разбивку (пагинацию)**.

---

## Сигнатура метода

```python
async def symbol_params_many(
    request: SymbolParamsManyRequest,
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[asyncio.Event] = None,
):
```

Ключевые моменты:

* Метод асинхронный и вызывается с `await`
* Параметры запроса передаются через объект `SymbolParamsManyRequest`
* Настройки пагинации указываются в запросе
* Метод возвращает одну страницу данных за вызов

---

## 🧩 Пример кода — Перебор всех страниц

```python
async def get_all_symbols(account):
    all_symbols = []
    page_number = 0
    items_per_page = 100

    while True:
        request = account_helper_pb2.SymbolParamsManyRequest()
        request.page_number = page_number
        request.items_per_page = items_per_page

        data = await account.symbol_params_many(request)

        all_symbols.extend(data.symbol_infos)
        print(f"Page {page_number}: Retrieved {len(data.symbol_infos)} symbols")

        if len(all_symbols) >= data.symbols_total:
            break

        if len(data.symbol_infos) == 0:
            break

        page_number += 1

    print(f"Total symbols retrieved: {len(all_symbols)}")
    return all_symbols
```

В этом примере метод `symbol_params_many()` используется внутри цикла для последовательного получения всех страниц.

---

## 🟢 Подробное объяснение

---

### 1️⃣ Инициализация параметров пагинации

```python
page_number = 0
items_per_page = 100
```

* `page_number` задаёт номер страницы (нумерация начинается с `0`)
* `items_per_page` определяет максимальное количество символов на странице

Размер страницы выбирается пользователем исходя из баланса между скоростью и объёмом данных.

---

### 2️⃣ Формирование запроса

```python
request = account_helper_pb2.SymbolParamsManyRequest()
request.page_number = page_number
request.items_per_page = items_per_page
```

На каждом шаге цикла:

* создаётся новый объект запроса
* в нём задаются параметры текущей страницы

Метод не хранит состояние пагинации — всё управление страницами лежит на стороне пользовательского кода.

---

### 3️⃣ Получение одной страницы данных

```python
data = await account.symbol_params_many(request)
```

На этом шаге:

* выполняется один асинхронный вызов
* сервер возвращает одну страницу символов
* ответ содержит:

  * список параметров символов для текущей страницы
  * общее количество символов (`symbols_total`)

---

### 4️⃣ Накопление результатов

```python
all_symbols.extend(data.symbol_infos)
```

Полученные данные добавляются в общий список.

API не агрегирует страницы автоматически — это делается вручную в пользовательском коде.

---

### 5️⃣ Условия выхода из цикла

```python
if len(all_symbols) >= data.symbols_total:
    break
```

Цикл завершается, когда:

* количество собранных символов достигает общего числа

---

```python
if len(data.symbol_infos) == 0:
    break
```

Дополнительная проверка безопасности:

* если сервер вернул пустую страницу
* дальнейшие запросы не имеют смысла

---

### 6️⃣ Переход к следующей странице

```python
page_number += 1
```

После обработки текущей страницы номер увеличивается, и цикл продолжается.

---

## Роль низкоуровневого метода

Чёткая граница ответственности:

**`symbol_params_many()`**:

* возвращает одну страницу параметров символов
* сообщает общее количество символов
* не управляет пагинацией
* не агрегирует данные

**`get_all_symbols()`**:

* управляет номерами страниц
* накапливает результаты
* определяет условия завершения
* формирует итоговый список

---

## Итог

Этот пример демонстрирует стандартный паттерн работы с постраничными низкоуровневыми методами:

> **запросить страницу → обработать данные → проверить условия → запросить следующую страницу**

Метод `symbol_params_many()` предоставляет доступ к данным по страницам, а вся логика перебора и агрегации реализуется на стороне пользовательского кода.
