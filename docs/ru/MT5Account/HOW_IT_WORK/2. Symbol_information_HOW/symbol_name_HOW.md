## symbol_name — Как это работает

---

## 📌 Обзор

Этот пример показывает, как получать **имена торговых символов по индексу** с помощью низкоуровневого асинхронного метода `symbol_name()` и как на его основе безопасно построить список символов с обработкой ошибок.

Сам метод `symbol_name()` очень прост — он возвращает имя символа по заданному индексу. Однако на практике он почти всегда используется **в паре с `symbols_total()`** и внутри цикла.

---

## Сигнатура метода

```python
async def symbol_name(
    index: int,
    selected: bool,
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[asyncio.Event] = None,
):
```

Ключевые моменты:

* Метод асинхронный и вызывается с `await`
* `index` — индекс символа (нумерация начинается с `0`)
* `selected` определяет, откуда берётся список символов:

  * `True` — только символы из «Обзора рынка» (Market Watch)
  * `False` — все доступные символы
* Метод возвращает объект с именем символа

---

## 🧩 Пример кода — Безопасное получение списка символов

```python
async def get_symbols_safe(account, selected_only: bool = True) -> list[str]:
    symbols = []

    try:
        count_data = await account.symbols_total(selected_only=selected_only)
        total = count_data.total

        for i in range(total):
            try:
                symbol_data = await account.symbol_name(index=i, selected=selected_only)
                symbols.append(symbol_data.name)
            except Exception as e:
                print(f"Error getting symbol at index {i}: {e}")
                continue

        print(f"Successfully retrieved {len(symbols)} out of {total} symbols")

    except Exception as e:
        print(f"Error getting symbol count: {e}")

    return symbols
```

Этот пример демонстрирует устойчивый к ошибкам способ перебора списка символов.

---

## 🟢 Подробное объяснение

---

### 1️⃣ Получение количества символов

```python
count_data = await account.symbols_total(selected_only=selected_only)
total = count_data.total
```

На этом шаге:

* выполняется отдельный низкоуровневый вызов
* сервер возвращает общее количество символов
* это значение используется как граница цикла

Без этого шага невозможно корректно использовать `symbol_name()`.

---

### 2️⃣ Перебор индексов

```python
for i in range(total):
```

Код перебирает все возможные индексы:

* каждому индексу соответствует один символ
* порядок определяется сервером

Индексы не являются стабильными идентификаторами символов.

---

### 3️⃣ Получение имени символа по индексу

```python
symbol_data = await account.symbol_name(index=i, selected=selected_only)
```

На этом шаге:

* выполняется один асинхронный вызов
* сервер возвращает имя символа для данного индекса
* имя доступно в поле `symbol_data.name`

Метод не возвращает никакой дополнительной информации о символе.

---

### 4️⃣ Локальная обработка ошибок

```python
except Exception as e:
    print(f"Error getting symbol at index {i}: {e}")
    continue
```

Здесь реализована важная защитная логика:

* ошибка при получении одного символа не прерывает весь процесс
* проблемный индекс просто пропускается
* цикл продолжается

Это особенно важно при работе с большими списками символов.

---

### 5️⃣ Обработка ошибки получения количества символов

```python
except Exception as e:
    print(f"Error getting symbol count: {e}")
```

Если общее количество символов получить не удалось:

* дальнейший перебор невозможен
* функция возвращает пустой список

---

## Роль низкоуровневого метода

Чёткая граница ответственности:

**`symbol_name()`**:

* возвращает имя символа по индексу
* не знает общего количества символов
* не управляет перебором списка
* не обрабатывает ошибки перебора

**`get_symbols_safe()`**:

* получает количество символов
* управляет циклом
* обрабатывает ошибки
* формирует итоговый список

---

## Итог

Этот пример иллюстрирует стандартный паттерн работы с низкоуровневыми методами на основе индексов:

> **получить размер → перебрать → обработать ошибки → собрать результат**

Метод `symbol_name()` предоставляет минимальный доступ к данным, а вся логика перебора и устойчивости реализуется на стороне пользовательского кода.
