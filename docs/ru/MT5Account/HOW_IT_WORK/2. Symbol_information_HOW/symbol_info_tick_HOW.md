## symbol_info_tick — Как это работает

---

## 📌 Обзор

Этот пример показывает, как использовать низкоуровневый асинхронный метод `symbol_info_tick()` для получения текущего тика по символу и выполнения **собственной валидации рыночных данных перед торговлей**.

Тик — это последняя доступная рыночная информация (Bid, Ask, время и т. д.). Сам по себе он не гарантирует, что данные пригодны для торговли, поэтому в примере сразу показано, как эти данные проверяются на стороне пользователя.

---

## Сигнатура метода

```python
async def symbol_info_tick(
    symbol: str,
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[asyncio.Event] = None,
):
```

Ключевые моменты:

* Метод асинхронный и вызывается с `await`
* `symbol` — имя торгового символа
* Метод возвращает объект с последним известным тиком
* Метод не выполняет проверок корректности данных

---

## 🧩 Пример кода — Валидация тика перед торговлей

```python
async def validate_tick(account, symbol: str) -> bool:
    try:
        tick = await account.symbol_info_tick(symbol)

        if tick.bid <= 0 or tick.ask <= 0:
            print(f"Invalid prices: bid={tick.bid}, ask={tick.ask}")
            return False

        spread = tick.ask - tick.bid
        if spread <= 0:
            print(f"Invalid spread: {spread}")
            return False

        if tick.time_utc > 0:
            current_time = datetime.now(timezone.utc).timestamp()
            age = current_time - tick.time_utc

            if age > 10:
                print(f"Tick too old: {age} seconds")
                return False

        print("Tick validation passed")
        return True

    except Exception as e:
        print(f"Validation error: {e}")
        return False
```

Этот пример демонстрирует типичную проверку безопасности, которая выполняется **перед отправкой торговых операций**.

## 🟢 Подробное объяснение

---

### 1️⃣ Получение последнего тика

```python
tick = await account.symbol_info_tick(symbol)
```

На этом шаге:

* выполняется один асинхронный вызов
* терминал возвращает последний известный тик по символу
* объект `tick` содержит цены и время

Метод возвращает данные «как есть», без интерпретации.

---

### 2️⃣ Проверка цен Bid и Ask

```python
if tick.bid <= 0 or tick.ask <= 0:
```

Проверяется наличие корректных цен:

* значения `<= 0` указывают на отсутствие действительных котировок
* такие данные нельзя использовать для торговли

---

### 3️⃣ Проверка спреда

```python
spread = tick.ask - tick.bid
if spread <= 0:
```

Здесь проверяется логическая корректность цен:

* Ask должен быть больше Bid
* спред должен быть положительным

---

### 4️⃣ Проверка актуальности тика

```python
if tick.time_utc > 0:
    current_time = datetime.now(timezone.utc).timestamp()
    age = current_time - tick.time_utc
```

Время тика сравнивается с текущим временем:

* `tick.time_utc` — метка времени Unix
* возраст тика вычисляется в секундах

---

```python
if age > 10:
```

В примере используется собственное правило:

* тик старше 10 секунд считается непригодным для торговли

Это не правило API, а решение прикладного кода.

---

### 5️⃣ Успешная валидация

```python
print("Tick validation passed")
return True
```

Если все проверки пройдены, тик считается действительным.

---

### 6️⃣ Обработка ошибок

```python
except Exception:
    return False
```

Любая ошибка при получении или проверке тика приводит к запрету торговли.

---

## Роль низкоуровневого метода

Чёткая граница ответственности:

**`symbol_info_tick()`**:

* возвращает последний тик
* не проверяет его корректность
* не оценивает актуальность данных

**`validate_tick()`**:

* проверяет цены
* проверяет спред
* проверяет возраст тика
* принимает решение, разрешена ли торговля

---

## Итог

Этот пример иллюстрирует базовый паттерн работы с низкоуровневым API:

> **низкоуровневые данные → собственная валидация → торговое решение**

Метод `symbol_info_tick()` предоставляет сырые рыночные данные, а вся логика их интерпретации и валидации остаётся на стороне пользователя.
