## account_summary — Как это работает

---

## 📌 Обзор

Этот пример демонстрирует, как получить **сводку по торговому счёту** с помощью низкоуровневого асинхронного метода `account_summary()`.

В отличие от методов `account_info_*`, которые возвращают одно конкретное значение, `account_summary()` используется, когда нужно **несколько связанных параметров счёта сразу**.

Метод выполняет **один запрос** и возвращает объект с заранее собранными данными о состоянии счёта.

---

## Сигнатура метода

```python
async def account_summary(
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[asyncio.Event] = None,
):
```

Ключевые моменты:

* Метод асинхронный и должен вызываться с `await`
* Параметры `deadline` и `cancellation_event` управляют временем выполнения
* Метод не принимает `property_id`, потому что возвращает **набор значений**, а не одно поле

---

## 🧩 Пример кода — Оценка торгового риска

```python
async def assess_trading_risk(account: MT5Account) -> str:
    summary = await account.account_summary()

    # Вычисление факторов риска
    balance = summary.account_balance
    equity = summary.account_equity
    leverage = summary.account_leverage

    # Оценка риска
    if leverage > 200:
        risk = "HIGH"
    elif leverage > 100:
        risk = "MEDIUM"
    else:
        risk = "LOW"

    # Проверка текущих убытков
    if equity < balance * 0.9:
        risk = "HIGH"

    print(f"Risk Assessment: {risk}")
    print(f"  Leverage: 1:{leverage}")
    print(f"  Balance: ${balance:.2f}")
    print(f"  Equity: ${equity:.2f}")

    return risk
```

В этом примере `account_summary()` используется для получения текущего состояния счёта и последующей оценки уровня торгового риска.

---

## 🟢 Подробное объяснение

---

### 1️⃣ Получение данных сводки по счёту

```python
summary = await account.account_summary()
```

На этом шаге выполняется один асинхронный вызов.

* Метод запрашивает всё состояние счёта
* Результат — объект `summary`
* Повторные вызовы API для чтения отдельных полей не требуются

После этой строки все необходимые данные уже доступны локально.

---

### 2️⃣ Извлечение значений из сводки

```python
balance = summary.account_balance
equity = summary.account_equity
leverage = summary.account_leverage
```

Здесь не происходит обмена с сервером.

* `summary` — обычный объект Python
* Значения доступны как атрибуты
* Чтение полей — локальная операция

Каждая строка просто извлекает нужный параметр из уже полученного снимка состояния счёта.

---

### 3️⃣ Первичная оценка риска по кредитному плечу

```python
if leverage > 200:
    risk = "HIGH"
elif leverage > 100:
    risk = "MEDIUM"
else:
    risk = "LOW"
```

Начинается прикладная логика оценки риска.

* Используется только значение кредитного плеча
* Заданы пороговые значения
* Выбирается базовый уровень риска

Эти пороги являются частью пользовательской логики и не связаны с работой API.

---

### 4️⃣ Дополнительная проверка текущих убытков

```python
if equity < balance * 0.9:
    risk = "HIGH"
```

Вторая проверка дополняет первоначальную оценку.

* Текущие средства (equity) сравниваются с балансом
* Если убытки превышают заданный порог, риск повышается

Здесь используется обычное арифметическое сравнение без каких-либо особых правил.

---

### 5️⃣ Вывод и возврат результата

```python
print(f"Risk Assessment: {risk}")
...
return risk
```

В конце функции:

* Выводится итоговая оценка риска
* Возвращается строковое значение уровня риска

Что делать с этим результатом дальше — решает вызывающий код.

---

## Итог

В этом примере `account_summary()` используется как источник **снимка состояния счёта**.

Один вызов API возвращает набор связанных параметров, после чего вся логика анализа и принятия решений выполняется локально, без дополнительных запросов к серверу.
