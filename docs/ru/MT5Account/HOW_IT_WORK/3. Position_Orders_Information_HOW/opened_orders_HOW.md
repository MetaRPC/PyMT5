## opened_orders — Как это работает

---

## 📌 Обзор

Этот пример показывает, как использовать низкоуровневый асинхронный метод `opened_orders()` для получения **текущего снимка состояния торгового счёта**:

* список отложенных ордеров
* список открытых позиций

Метод используется для мониторинга счёта, отображения торгового состояния и принятия последующих решений.

---

## Сигнатура метода

```python
async def opened_orders(
    sort_mode: BMT5_ENUM_OPENED_ORDER_SORT_TYPE = BMT5_OPENED_ORDER_SORT_BY_OPEN_TIME_ASC,
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[asyncio.Event] = None,
):
```

Ключевые моменты:

* Метод асинхронный и вызывается с `await`
* `sort_mode` влияет **только на порядок отложенных ордеров**
* позиции возвращаются без сортировки
* Метод возвращает один агрегированный объект состояния

---

## 🧩 Пример кода — Получение открытых ордеров и позиций

```python
data = await account.opened_orders(
    sort_mode=account_helper_pb2.BMT5_OPENED_ORDER_SORT_BY_OPEN_TIME_ASC,
    deadline=deadline
)

print(f"Pending orders: {len(data.opened_orders)}")
print(f"Open positions: {len(data.position_infos)}")

# Показать позиции
for pos in data.position_infos:
    print(
        f"Position #{pos.ticket} {pos.symbol}: "
        f"{pos.volume} lots @ {pos.price_open}, P/L: ${pos.profit:.2f}"
    )

# Показать ордера
for order in data.opened_orders:
    print(
        f"Order #{order.ticket} {order.symbol}: "
        f"{order.volume_initial} lots @ {order.price_open}"
    )
```

Этот пример демонстрирует работу с результатом без дополнительной фильтрации или преобразований.

## 🟢 Подробное объяснение

---

### 1️⃣ Вызов метода opened_orders

```python
data = await account.opened_orders(
    sort_mode=account_helper_pb2.BMT5_OPENED_ORDER_SORT_BY_OPEN_TIME_ASC,
    deadline=deadline
)
```

На этом шаге:

* выполняется один асинхронный запрос
* сервер формирует текущее торговое состояние счёта
* данные возвращаются как один объект

Этот объект представляет собой **снимок состояния в конкретный момент времени**.

---

### 2️⃣ Структура результата

Ответ содержит два независимых списка:

```python
data.opened_orders     # отложенные ордера
data.position_infos    # открытые позиции
```

Это принципиально разные сущности:

* позиции — уже открытые сделки
* ордера — инструкции, ожидающие исполнения

Они возвращаются вместе, потому что отражают одно и то же состояние счёта.

---

### 3️⃣ Подсчёт ордеров и позиций

```python
len(data.opened_orders)
len(data.position_infos)
```

Здесь:

* списки уже сформированы сервером
* клиент просто считает элементы

Метод не фильтрует и не скрывает данные.

---

### 4️⃣ Перебор открытых позиций

```python
for pos in data.position_infos:
```

Каждый элемент в списке позиций содержит набор полей, например:

* `ticket` — идентификатор позиции
* `symbol` — торговый инструмент
* `volume` — объём позиции
* `price_open` — цена открытия
* `profit` — текущая прибыль или убыток

Пользовательский код:

* выбирает нужные поля
* форматирует вывод
* решает, что считать важным

---

### 5️⃣ Перебор отложенных ордеров

```python
for order in data.opened_orders:
```

Отложенные ордера:

* не имеют текущей прибыли
* используют `volume_initial` вместо `volume`
* существуют отдельно от позиций

Это подчёркивает, почему метод возвращает два разных списка.

---

### 6️⃣ Роль параметра sort_mode

```python
sort_mode=BMT5_OPENED_ORDER_SORT_BY_OPEN_TIME_ASC
```

Важно:

* сортировка применяется **только к отложенным ордерам**
* позиции не сортируются
* сортировка выполняется на стороне сервера

Клиент получает уже упорядоченный список ордеров.

---

## Роль низкоуровневого метода

Чёткая граница ответственности:

**`opened_orders()`**:

* возвращает текущее состояние ордеров и позиций
* агрегирует данные на стороне сервера
* не фильтрует и не анализирует их
* не принимает торговых решений

**Пользовательский код**:

* решает, какие поля использовать
* как отображать данные
* какие действия выполнять дальше
