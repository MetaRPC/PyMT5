## positions_total — Как это работает

---

## 📌 Обзор

Этот пример показывает, как использовать низкоуровневый асинхронный метод `positions_total()` для получения **текущего количества открытых позиций** на счёте и сравнения его с заданным целевым значением.

Этот сценарий типичен для управления рисками и контроля торгового состояния:

* ограничение максимального количества позиций
* поддержание заданного количества сделок
* контроль перегрузки счёта

Метод используется исключительно как источник фактического состояния.

---

## Сигнатура метода

```python
async def positions_total(
    deadline: Optional[datetime] = None,
    cancellation_event: Optional[asyncio.Event] = None,
):
```

Ключевые моменты:

* метод асинхронный и вызывается с `await`
* не принимает фильтров или параметров
* возвращает **только количество открытых позиций**
* не выполняет проверок или сравнений

---

## 🧩 Пример кода — Сравнение количества позиций с целевым значением

```python
async def compare_with_target(
    account: MT5Account,
    target_positions: int
) -> dict:
    data = await account.positions_total()
    current = data.total_positions

    difference = current - target_positions

    result = {
        "current": current,
        "target": target_positions,
        "difference": difference,
        "status": "exact" if difference == 0 else "above" if difference > 0 else "below"
    }

    if difference == 0:
        print(f"[OK] Exactly at target: {current} positions")
    elif difference > 0:
        print(f"[INFO] {abs(difference)} above target ({current}/{target_positions})")
    else:
        print(f"[INFO] {abs(difference)} below target ({current}/{target_positions})")

    return result
```

Этот пример демонстрирует прикладную проверку торгового состояния относительно заданного лимита.

---

## 🟢 Подробное объяснение

---

### 1️⃣ Получение текущего количества позиций

```python
data = await account.positions_total()
current = data.total_positions
```

На этом шаге:

* выполняется один асинхронный запрос
* сервер возвращает количество **открытых** позиций
* никакая дополнительная информация не передаётся

Метод возвращает текущее состояние, а не историю.

---

### 2️⃣ Сравнение с целевым значением

```python
difference = current - target_positions
```

Здесь начинается пользовательская логика:

* вычисляется отклонение от целевого значения
* положительное значение означает превышение лимита
* отрицательное значение означает недостаток позиций

---

### 3️⃣ Формирование статуса

```python
status = "exact" if difference == 0 else "above" if difference > 0 else "below"
```

Статус полностью определяется пользователем:

* `exact` — текущее количество совпадает с целевым
* `above` — позиций больше, чем нужно
* `below` — позиций меньше, чем требуется

API не интерпретирует результат.

---

### 4️⃣ Реакция на результат

```python
if difference == 0:
    ...
elif difference > 0:
    ...
else:
    ...
```

На этом шаге:

* принимается решение
* выполняется логирование
* при необходимости здесь может быть торговая логика (закрытие / открытие позиций)

---

### 5️⃣ Возврат агрегированного результата

```python
return result
```

Функция возвращает структуру с уже интерпретированным состоянием.

---

## Роль низкоуровневого метода

Чёткая граница ответственности:

**`positions_total()`**:

* возвращает только количество открытых позиций
* не знает, что означает «цель» или «лимит»
* не принимает решений

**Пользовательский код**:

* задаёт целевое значение
* сравнивает текущее состояние с целевым
* интерпретирует результат
* предпринимает дальнейшие действия

---

## Итог

Этот пример иллюстрирует простой, но важный паттерн контроля состояния:

> **получить текущее значение → сравнить с целью → принять решение**

Метод `positions_total()` предоставляет фактическое состояние счёта, а вся логика контроля и управления реализуется на стороне пользователя.
